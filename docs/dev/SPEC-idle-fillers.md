<a name="spec-idle-fillers-用户得到什么"></a>
## 用户得到什么

人物知道什么时候会再被请去决策、哪些事到点会请他决策而手上的活动照常进行；想消遣时选择 app，环境只在这个 app 内抽取已绑定的内容。等待只留给几分钟内就有事请他决策的时候，不再把「刷手机」当成没有内容依据的填充活动。
作息与今日计划里的钟点只是大概：差不多到了就做，非准点不可的事靠目标的提醒时刻。
零点计划不再把天天如此的作息与消遣写成目标，目标文字少写钟点，要按时起床、按时出门的事才填提醒时刻。
声明了工作安排的人物醒着时在班次与休息时段的起止当秒得到一次决策机会，进行中的活动照常继续，睡着的人不被叫醒。

```mermaid
flowchart LR
    C[C 班次与休息时段起止<br/>四个唤醒原因] --> A[A 系统层第 7、14、15、16 条<br/>何时再请决策与钟点只是大概]
    A --> B[B 零点计划模板第三、五、六条<br/>少写作息与钟点，按时的事填提醒]
    B --> BASE[当前完整日工件核验<br/>原有业务断言与实际存储]
    BASE --> GATE[门禁、变异审查与验收记录]
```

环境不替人物选择 app；选定 app 后，环境按该 app 的推送与全局内容进度抽取内容。等待没有占比上限，始终列出、照常受理；本特性不让等待自动延长，不给等待加时长字段，不让提醒自动结束等待，不把 `around_time` 做成提醒。
人物工具面、七层 Schema、世界结构 9、质量报告结构 4 与 AS2 补丁不因本特性改变。
本特性实施基线的场景结构为 5；当前主线因[环境数据归属规格](SPEC-environment-data-ownership.md)升为 6，
正式环境位于 WorldMock-Dataset 的 `environment/zhangjiang-baseline/`，必须显式选择，旧结构 5 不保留读取分支。

第 15 条

第 16 条
晚上照人设层作息里的就寝时间去睡（没写就寝时间，就困了再睡）：有点乏、困是睡前的常态，还没到就寝时间就照常过晚上，到了就可以睡，不用撑到某个钟点；很困或撑不住了可以提前，精神还好也可以晚些。想在某个时刻起来，就给今日计划的目标写上提醒时刻；睡着时只有提醒或睡够了才会醒，早睡也就早醒。

<a name="spec-idle-fillers-班次边界唤醒"></a>
## C：班次与休息时段起止的唤醒

<a name="spec-idle-fillers-班次边界规则"></a>
### 规则

某个结算边界的那一秒如果是某人工作安排中某个本地日班次的开始或结束（含前一日写到 24:00、落在当日零点的结束），或该班次某个休息时段的开始或结束，而他此刻没有在睡，他就在这一秒得到一次决策机会；其余什么都不发生。

- 阶段 5 删除三个工作相关名字，现行 `WakeReason` 为最终 22 项；班次与休息时段四项及 `app_push` 均保留。睡眠允许集合仍只有四项。
- 四个成员都不进入睡眠允许集合，`src/worldmock/life/schedule.py::SLEEP_ALLOWED_REASONS` 逐字节不动；睡着的人不计入下一边界与下一次决策机会的候选，不形成静默边界，不被叫醒，睡过的起止醒来后不补。
- 不结束、不暂停、不开始任何活动：活动状态、计划结束时刻与下一次交互时刻都不变；不新增拒绝，不写事件，不新增进度层记录；唤醒原因不进提示，人物看到的变化只有环境层 `duty.status` 与观察时刻。
- 起止时刻由场景工作安排与世界时钟直接求值，不存交付状态：日期例外优先于每周声明，区间半开，按当地墙钟换算（R7），写作 1440 的止点落在次日当地零点；不当班的日子本身没有起止（前一日写到 24:00 的结束照记），没有工作安排的人物没有这些时刻。
- 同一秒重合的多个起止各记一次，按枚举次序并列，与同一秒的其他原因合为一次机会。
- 当日目标的大致时刻与人设层作息的钟点不属于这一条，本身不触发决策（午餐、晚餐窗口起止只在体感跨档时提供机会）。
- 世界结构 9、质量报告结构 4、当前场景结构 6 不因本特性升级；两个指纹不变；变化只由 `code_sha256` 绑定。AS2 补丁不含唤醒原因内容，不改。

<a name="spec-idle-fillers-班次边界情形"></a>
### 各种情形

| 情形 | 行为 |
| --- | --- |
| 清醒，有进行中的活动 | 边界恰在起止，一次机会，活动继续 |
| 在起止上做完决策之后 | 请求被受理且仍有进行中的活动时，下一次决策时刻移到下一个候选，同一秒不再就绪；被拒或把活动结束时，照既有的同刻规则在同一秒再决策；两种情形下之后的决策都不再带这个名字 |
| 睡着（世界里只有他，或所有人都睡着） | 两条路径都没有候选，起止不成为边界；那一秒本来就是边界时（例如当地零点）他的结算静默 |
| 睡着，而别人的起止形成了边界 | 他的结算静默，睡眠继续 |
| 恰在起止那一秒因别的原因醒来（计划结束，或闹钟撞上同秒开始的班次） | 判定时已经清醒，起止照记，排在已有原因之后 |
| 没有进行中的活动 | 活动恰在这一秒结束时，起止与 `planned_end`、`no_active_activity` 并列在这一秒的第一次决策里；同刻决策预算耗尽后的技术性暂停期间，起止是时钟边界，记 `no_active_activity` 与起止，暂停随之结束 |
| 零点上的起止（班次写到 24:00，或从 00:00 开始） | 当地零点本来就是边界，由零点节律入口在零点计划之后判定；零点恰是运行结束时在推进内判定 |
| 写到 24:00 的班次，次日休息 | 00:00 记 `shift_end`，此时环境层已是次日的 `duty`，这种班次看不到「已下班」；如实记录，不修 |
| 休息日、日期例外 | 由 `src/worldmock/life/work_schedule.py::shift_on` 决定，例外优先；不当班就没有起止 |
| 没有工作安排 | 没有任何新增边界 |
| 在路上、在通话或交谈中 | 有机会；可以播报、结束、再开一项、发消息；暂停照现在的规则被拒 |
| app 内容完成 | 内容完成先静默更新人物的全局 `content_progress`；若同秒也命中班次边界，人物得到一次带班次原因的机会，正在进行的 app 活动与下一次交互时刻按结算结果继续 |
| 运行开始恰在起止上 | 第一秒只记 `run_start`，不记起止；第一次观察的 `duty.status` 已呈现该状态 |
| 检查点与恢复、反事实重演 | 不为起止另存状态，起止按场景与时钟重新求值；已经判定而尚未决策的原因照常留在人物状态的 `pending_wake_reasons` 里随检查点恢复，不重复、不补发 |

设计刻意不做的事：不按处境收窄（在路上或不在岗也给机会）；不给模型新的进度层记录；`around_time` 不被任何新代码读取。

迭代用针对文件的 pytest；合并前跑标准层；特性验收跑全量层与覆盖率门禁（分支覆盖率不低于 85%、未覆盖公共接口为零）；另有风格门禁、导入图与单一来源守卫、文档门禁、设计汇编核对。不用延期标记，不用跳过。

- 本机（Windows）环境已重新引导，`require_locked_as2` 通过。主检出在 `core.autocrlf=true` 下有 CRLF 的 Markdown 与没有固定换行属性的 CRLF 文件：文档门禁对归档快照的逐字节比对会失败，与字节相关的检查结果也会与 LF 检出不同；门禁与字节相关的检查一律在 `core.autocrlf=false` 的独立工作树里执行，结果对同一提交成立。

<a name="spec-idle-fillers-已知局限"></a>
## 已知局限

- 效果没有保证：纸面推演按定稿估计仍会等约 7 次，其中离事件不到六分钟的两次属于留给等待的正当情形；这些是对模型读法的推断，不是测量。
- 「几分钟」「差不多」「早一点晚一点」没有数值（D11）；模板第五、六条只靠文字，`plan_day` 关闭了思考，效果看复跑。
- 提醒变多也会成为等的对象；人物白天自己设的提醒同样如此。
- 同一意图只写一条目标的约束不改（见 B）。
- 运行开始晚于平常起床时，第三条的起床提醒可能早于生成时刻而被退回重试，第四次仍无效按运行故障停止；复跑观察启动路径的重试。
- 完整日签名的平台差异不修，见「门禁与平台」。
- 写到 24:00 的班次次日休息时看不到「已下班」（见「各种情形」）。
