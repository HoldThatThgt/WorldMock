## 审查结论

提案可以形成一个贯穿发现、比较、出行、购买、履约与恢复的完整特性，但不能仅把商品增加一个门店字段。
必须同时修正地点定义的唯一来源、活动环境声明、供给身份、营业求值、道路范围、候选身份、事件证据和恢复身份。
这些内容跨越既有冻结合同；最终规格应明确裁决后的范围，并把提案改为设计依据。

```mermaid
flowchart LR
    P[提案与行业证据] --> S[裁决后的特性规格]
    S --> C[接口合同与记录合同]
    C --> D[设计文档与实验条件]
    D --> I[正式数据与实现]
    I --> T[条款到具体测试]
    T --> B[独立源码突变与恢复验证]
    B --> V[带源码身份的验收记录]
```

冻结前审查只执行文档链接基线，未执行全量测试、模拟验收或源码突变；该阶段测试列是验收义务，不是通过证明。
行业事实的最终采纳以并行行业研究及父任务裁决为准，本审查不把提案中的研究描述当作已核验事实。

父任务已明确采用已有张江真实地点及显式供给假设，完整实现发现、比较、出行、购买与履约。
访问资格可以声明并验证，但不新增会员购买、预约动作或物品搬运；发现遵循既有单生活动作及后轮结果合同。
初始冻结资料包含二百二十份按出行方式命名的响应；其中一百零四份步行文件错误复用驾车响应。
“只有十二条冻结路线”与“二百二十条方式均已核验”都不是准确结论。后续实现已修订路线资料和方式准入，
原始资料存在、实际路段方式、正式场景引用和端到端行为仍是不同证据，不能互相替代。

## 权威归属与不可混淆的概念

| 内容 | 唯一规范位置 | 本次约束 |
| --- | --- | --- |
| 接口、字段、枚举、请求、场景结构 | `docs/CONTRACTS.md` | 新规格引用字段合同，不能另立第二套签名 |
| 事件正文、资产、检查点、足迹导出与恢复 | `docs/design/05-recording-engine.md` | 新特性证据首先写入此处，其余文档引用 |
| 地图与门店供给行为 | `SPEC-map-and-storefront.md` | 冻结全部行为及验收；被替代的既有规格句子必须同步修订 |
| 四个引擎的职责 | `docs/ARCHITECTURE.md` 与所属引擎设计 | 不新增地图引擎、第二个世界状态写入方或在线运行服务 |
| 地图区域、日期、许可、版本和供给假设 | `docs/EXPERIMENT.md` 与资源引擎设计 | 真实地点、路线取得时间与实验日期的差异必须可见 |
| 通过条件与实测状态 | `docs/VERIFICATION.md`、`docs/dev/implementation-status.md` | 规格冻结、代码实现、测试通过和真实实验通过分别陈述 |

| 概念 | 应固定的语义 | 必须排除的混用 |
| --- | --- | --- |
| 地图数据集合 | 固定区域、坐标系、时区、来源与版本的地点和路线资料 | 不能与可变世界状态或在线地图服务同义 |
| 地点 | 稳定身份和坐标的场所，可经营也可不经营 | 不以品牌或经营业态代替地点身份 |
| 门店供给 | 地点、商品或服务、卖方账户共同标识的供给 | 库存、报价、履约不能再按商品身份共用 |
| 品牌 | 可缺省且有来源的地点属性 | 无品牌地点有效；同品牌不能推断同价格、库存或资格 |
| 经营业态 | 地点经营什么 | 不代替活动环境或交互菜单地点类 |
| 活动环境 | 地点显式声明能承载哪些活动环境 | `location_kinds` 必填且非空，不从业态名称自动推导 |
| 交互菜单地点类 | 地点单值 `kind` 用于取得地点菜单 | 与活动环境多值集合相互独立，不能顺手合并 |
| 商品 | 固定的产品定义与取得后持有物的身份 | 报价和卖方属于门店供给，不属于商品的固有语义 |

## 冻结前冲突与采纳裁决

| 冲突 | 直接证据 | 建议裁决及影响 |
| --- | --- | --- |
| 提案仍禁止被实现依赖 | 提案头部、`docs/INDEX.md`「权威层级」 | 建立完整冻结规格，提案改为已裁决设计记录；日期不能保留尚未发生的 2026-09-21 为本次审查日期 |
| 地点活动环境缺字段却自动放行 | `LocationConfig` 无 `location_kinds`；`retrieval.place_kinds`、`presentation._location_kinds`、`activities.require_location_kinds` 存缺省路径；已有测试明确接受缺声明 | 正式地点目录必填显式活动环境，正式场景引用该定义；删除缺失转 `anywhere` 和缺失即放行的路径及旧断言 |
| 地点发现与单动作协议可能冲突 | `docs/CONTRACTS.md`「人物工具与管理接口」「动作状态与动作结果」；`browse_activities` 登记后跨轮返回 | 地图发现也遵循动作登记、结算、`action_result`、下次观察；如改为当轮世界查询，必须明确重写冻结协议并覆盖单观察、单动作和预算，不能隐式绕过 |
| 候选身份仍以商品为单位 | `CandidateKind`、商品可见期、`presentation_state`、动态购买 Schema | 购买候选与可见性必须按门店供给，库存物和消费仍按商品；同商品两家门店不能去重成一个候选或共享呈现时刻 |
| 查询地点可达与购买资格不同 | 提案要求不可达地点仍可发现，候选资格会排除地点不在场、关门、售罄 | 地点发现保留真实地点及可达、营业、供给状态；购买可行性另判，不因当前不可买而删除地点身份 |
| 空间查询与确定性索引禁令的措辞冲突 | 既有规格禁止索引含浮点距离或近似近邻；提案希望 AS2 空间粗筛 | 允许已验证的确定性地理粗筛作为道路查询输入；冻结道路结果决定可达范围，排序稳定且不得用直线距离替代道路分钟；不引入近似检索 |
| 商品价格仍从目录交换边派生 | `ScenarioSemantics` 组装 `ProductConfig.price_fen` 与 `price_version` | 报价声明迁入门店供给，商品固定效果保留；目录生成器、金额守恒验证和构建复现检查一并修改 |
| 整单只检查卖方账户一致 | `basket._order_rows` 仅检查 `merchant_account_id`，之后使用首件商品的地点与准备时间 | 采用同一地点且同一卖方的一次订单；不同门店整单明确拒绝。若采纳跨门店订单，则必须完整实现逐供给营业、履约与资金分录，不能套用首店 |
| 报价修改可能无法恢复 | `ScenarioSemantics.with_price` 保存更改的运行时语义，世界状态仅记录库存 | 有效报价必须是可恢复的当下事实；检查点后恢复不能回退到初始目录价；报价版本变化仍使旧请求失效 |
| 营业判断散落各路径 | `basket.py`、`commerce.py`、`observe.py`、`candidates.py`、`motivation.py`、`rhythm.py` 均直接判断 `open_hour` / `close_hour` | 所有读取统一使用同一冻结营业声明和当前例外求值；日历边界进入事件时钟，不允许观察开放但购买关闭 |
| 缺路线与已证不可达混同 | 当前 `RouteConfig` 只有成功路线；提案要求保留不可达结果 | 发布清单明确有限地点集合和方式范围，对每个应覆盖方向保存成功路线或来源支持的不可达结果；缺项拒绝发布 |
| 供给假设与历史事实易混同 | 提案采用真实地点和假设供给，实验为 2026 年一月至三月 | 来源记录保留采集日、事实截止日、适用范围与假设理由；营业、价格、库存不冒充原始地图的真实事实 |
| 提案时间字段只给出一部分边界 | 提案规定半开生效区间和未定义，但未定义重叠、过期核验范围 | 冻结唯一适用值、无重叠声明、发布审查日期和适用模拟时间的判据；未生效/已失效保持未定义，不取零或最近旧值 |
| 搬运、会员、预约、排队范围未裁决 | 提案「设计决策点」列为可选范围，既有规格明确无随身背包 | 核心范围采用既有到店即时自提和配送，取得物保留在取得地点；如纳入其他能力就给完整状态、动作、错误、恢复验收，不能写待补 |
| 覆盖率报告路径不一致 | `scripts/coverage_gate.py` 的 `REPORT_PATH` 是 `docs/coverage-report.json`，现行文档写 `docs/dev/coverage-report.json` | 整合时统一真实输出与文档指向；不能以旧 `docs/dev` 报告作为新 gate 证据 |
