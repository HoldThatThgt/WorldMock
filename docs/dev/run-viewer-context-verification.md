# 运行查看器上下文解析验证

## 交付与使用

打开 `tools/run-viewer.html`，载入 `footprints.sqlite` 后选择“上下文”。
可按人物、阶段和实际请求切换，查看内容块、完整原文、当前实现规则和同人物同阶段的前一次输入。
时间线中展开模型请求后，“查看上下文”可直接定位该次请求。
移动或分发查看器时，保留同目录的 `run-viewer-context.js`、`run-viewer-context-view.js` 和
`run-viewer-context.css`。没有新增第三方依赖，数据仍仅在浏览器中读取。

验收规范为 [SPEC-run-viewer-context.md](SPEC-run-viewer-context.md)。

## 实际运行验证

使用 `2026-09-28-c9a4fc1-day-r3` 的 `worldmock-export/events.jsonl.gz`，
将原始事件正文不作改写地装入临时 SQLite 事件表，验证真实查看器加载路径。
这份验证数据库仅补充运行时区，不伪造人物名称、订单、记忆或提示内容。

共加载 1,951 个事件、333 次模型请求：140 次自述、182 次行动，均能按当前模板无损拆分；
另有 11 次规划、归纳等调用，明确保留未解析的完整消息。
对全部 333 次请求逐条核对，每条消息和工具定义均能与原始记录完整对回。
浏览器检查了 10:43:01 请求的消息字段、规则切换、前后对照、自述阶段无工具、换文件清理，
没有 JavaScript 异常，桌面和窄屏均没有新增水平溢出。

历史请求没有保存填充来源边界，所以模板分段不是来源核验。场景正文恰好包含“主观归纳”标题时，
查看器保留这种不确定性；源码规则也不被当成该次运行保存的配置值。
此功能没有修复模拟中的消息截断、工时、任务或不足一份食物消费问题。

本机没有安装 Node.js：以 VS Code 自带的 Electron 作 Node 运行（`ELECTRON_RUN_AS_NODE=1`，版本 v24.20.0，含 `node:sqlite`），

复验覆盖的行为（夹具 `tests/fixtures/viewer-context.json` 含一份七层行动请求、一份续接形状的请求与旧运行的自述、行动请求各一份）：

- 行动请求只按「system 为 JSON 且 `layer` 为系统层、另有工具数组」识别；查看器的生活系统层与宿主 `LIFE_SYSTEM_LAYER`、夹具中的系统层逐字相同。
- 首个 user 按顶层数组无损切片为工具层、人设层、记忆层、待办层、环境层、进度层；字符串中的括号、逗号与转义引号不产生额外切片；
  层序错误、缺层、切片不可解析、首尾有多余空白，或首个 user 是结构化内容、消息带多余字段时显示为未解析并保留完整原文；语义解析定位首个 user，
  不假定它在第二条消息。
- 工具层逐目标列出动作与工具及其可用性；进度层按真实记录字段下钻，`self_note` 标「未经核验」。
- 首个请求多于两条消息时判为续接：六层照常切片，追加的消息整块显示；带来源的首个请求列出来源决策与回传的思考，各只一次；
  续接前缀中由更早决策写下的回复正文同样标「未经核验」。
- 旧运行的决策自述请求保持「其他调用·未解析」；旧行动请求按原模板识别并以「来源未核验」的推断分段，正文恰好含模板标题时仍是推断或退回未解析。
- 显式空工具保留，缺省工具不补占位；Unicode 字符合计每条消息只计一次；请求外壳畸形时保留归档原文、不捏造消息；
  同长异文的层变化与新增、退出按稳定身份区分并保留前后完整版本；每条解析规则都存在，增长视图保留明确来源与步骤。
