## 产品行为与边界

同一件商品可以在不同地点由不同卖方销售。人物实际看到地点、道路路程、营业状态、独立报价、库存和履约条件，自己选择去哪家或从哪家配送。世界仅判断条件并结算，不替人物选择。

```mermaid
flowchart LR
    D[冻结地图与商品定义] --> Q[人物发现与比较门店供给]
    Q --> T[人物选择出行或配送]
    T --> V[环境按当时事实重验]
    V --> P[整单付款与门店库存变化]
    P --> F[到店取得或配送交付]
    F --> U[取得地点的商品使用]
    Q & V & F --> E[观察、事件、来源与恢复证据]
```

本次使用现有张江区域，保留真实地点来源，门店商品、价格、库存、营业及访问规则可以是明确标记的场景假设。审查发现现有地图有十一处地点之间的二百二十份按方式命名的响应，其中一百零四份步行响应错误复用驾车结果。实现必须重新取得或明确改成资料未知，不能按文件名宣称方式已核实，也不得继续声称八处地点没有任何路线文件。

本次全部实现发现、比较、出行、购买、自提、配送、资格判断、营业时间、调价与补货、恢复和来源记录。访问资格是场景给定的事实，可以限制进入或服务；本次没有购买会员、预约办理、排队、背包或物品搬运动作。到店取得的物品留在该地点，配送物品在交付后位于目的地。这是完整行为范围，不是待实现占位。

商品、地点、门店供给、品牌、经营业态、活动环境保持各自含义；不创建第五个引擎。运行期间禁止在线地点、路由、库存或报价请求。不得保留旧结构适配、迁移命令或默认回退路径。

## 冻结输入与身份

| 对象 | 必须表达的内容 | 权威位置 |
| --- | --- | --- |
| 地图数据集合 | 稳定标识、版本、WGS84 坐标系、时区、区域、来源时间、许可与通知、文件哈希 | 冻结地图文件与语料清单 |
| 地点 | 标识、名称、坐标、经营业态、可选品牌、活动环境、营业声明、访问要求 | 地图地点目录 |
| 商品 | 身份、规格、用途、消费与使用效果 | 商品目录 |
| 门店供给 | 标识、地点、商品、卖方账户、报价声明、初始库存、履约方式与范围、处理时长、资格及来源 | 地图门店供给目录 |
| 场景引用 | 固定地图身份，选中的地点、商品、供给及库存初值，人物资格与账户实例 | 场景文档 |
| 运行时事实 | 按供给区分的库存和有效报价，营业例外，人物位置、资格、账户与已交付物品 | WorldState |

场景不重复地点的名称、坐标、营业声明或路线。地图文件引用冻结路线响应及路由实例、profile、取得时间和计算依据。地图可以保留未被当前场景选择的地点；运行时只允许引用已选地点和供给。

地点保留单值 `kind` 作为现有交互菜单分类，显式 `business_kind` 表示经营业态，非空 `location_kinds` 表示活动环境。活动环境闭集为 `home/office/outdoor/fitness/venue/anywhere`，不得从名称、品牌或经营业态自动推断；`anywhere` 是活动侧无地点限制的声明，不是地点资料缺失时的默认值。地点缺失活动环境必须拒绝。

门店供给使用稳定 `supply_id`；`(location_id, product_id, seller_account_id)` 必须唯一。多家供给可以引用同一个商品。卖方按 `account_id` 绑定，多个账户允许共享经营角色，人物账户和服务账户的身份仍必须唯一。

商品定义删除门店、卖方、库存、购买价格、报价版本和配送时长。商品目录不保留购买转账边；不发生消费交换的耐用品允许空交换边，不得伪造占位边。价格和库存不得再从商品对象推断。

地图发布必须验证版本与哈希、坐标边界、时区、来源/许可声明、字段日期、地点与供给唯一性、商品和账户引用、路线端点与方式、路线响应状态及完整选择范围。同一来源的事实时间和模拟日期不同必须显式标记适用限制。过期核对声明、缺必需关系、未知旧字段均拒绝并记录英文错误。

## 营业、报价与访问条件

营业与报价声明具有 `effective_from/effective_to`、`reviewed_on/still_valid_on` 及来源，生效区间为半开区间。所有时间明确时区，核对日期不得晚于可信截止日。相邻区间可以无缝切换，同类声明重叠必须拒绝；首个区间之前或声明间隙返回未知，不能推断全天营业、免费或可买。

营业按地点所在地图时区解释，支持每周多个分钟级开放区间、跨午夜、全天开放、明确闭店日期和日期例外。例外优先于每周规则；某日期明确闭店时不得继承前一日的跨午夜营业。营业结果为 `open/closed/unknown`，闭店和未知原因不同。营业例外作为世界事实保存，恢复不得丢失。

到达地点时重验访问资格，购买时重验营业、访问与供给资格、报价版本、库存、余额及履约条件。出发时的预测不构成到达或购买成功凭据；已完成的旅行不能因后续购买失败被抹掉。

有效报价与库存分别保存在 `WorldState.supply_quotes` 和 `WorldState.supply_stock`，键为供给身份。定义、观察与结算使用同一报价解释入口。调价、报价生效/失效和补货按模拟事件推进；营业变化进入既有事件时钟边界，禁止周期轮询。恢复必须继续使用持久化报价及库存，不能重载初始报价。

## 地点发现与候选呈现

`discover_places` 是一个生活动作，遵循现有登记、批次结算和下一次观察回灌；成功发现后安排下一秒的合法决策轮，及时回灌结果；不得成为人物在同轮同步查询世界后继续行动的旁路。模型只填写业务筛选条件；人物、决策与动作身份仍由宿主补齐。

查询接受可选商品需求、经营业态、出行方式和道路时间范围，返回匹配的具体地点及其门店供给。结果包含当前位置到目标的冻结路线身份、距离、分时预计时长、交通费、营业、访问资格、有效报价与版本、库存、支持的履约方式、来源与假设标记。未知条件不得伪装为已知否定。

供给行的 `purchase_allowed` 只表达当前营业、地点访问资格、供给资格、有效报价和正库存均满足，不表示余额、路线或特定履约请求已经通过结算校验。`pickup_allowed` 同时要求该供给支持自提且人物当前位于门店；成功购买仍以执行时的完整重验为准。

查询字段固定为 `product_id/business_kind/travel_mode/max_travel_seconds/cursor`，筛选值和首屏游标可为空但必须出现。发现结果按既有 `candidate_presentation_limit` 明确分页，保存 `total/next_cursor`，不得静默截断或把未呈现的后续页授权为可见。游标绑定地图身份、查询和起点，逐页仍使用当时事实；不能因查询本身提交新世界版本而使所有下一页失效。无筛选查询也必须能经过实际模型消息的字符预算校验。

分页单位是地点与供给的匹配行，无供给地点也占一行，按 `(location_id, supply_id)` 稳定排序。页内按地点聚合，`total/returned` 表示匹配行数，`returned_places` 表示本页地点数；同一地点的供给可以跨页出现。模型中的来源使用类型、来源引用与事实截止日，完整声明保留在对应观察、动作结果和清单；报价与路线比较事实不能删掉。直接下钻与有时长浏览回灌的公开 `excluded` 按全部非 `object_id` 属性分组，用 `object_ids` 保留每个对象身份；必须能还原全部逐项排除事实，原始结算证据保持逐项行。

地图必须为全部所选有向端点与方式声明 `reachable/unreachable/unknown` 三种状态之一，真正漏记录拒绝发布。地点存在但该方式不可达时，仍可被发现并明确标记 `unreachable`；尚未取得或无法核实资料的显式记录标记 `unknown` 并说明原因，不得冒充不可达。道路时间范围只依据冻结道路和已有分时公式；超范围、不可达与资料未知分别解释。明确未知的结果保留身份和原因，不能因无法计算距离就消失。已准备不可达记录必须有原始响应与哈希，出行动作给出明确拒绝原因；未知记录不允许出行。

空间索引只可以粗筛地点；AS2 的 protobuf Map 和数据库不是现有 OSM JSON 的直接适配接口。本次使用已有依赖与冻结地点数据，按明确道路信息查询，无须新增在线地图服务或空间基础设施。任何直线距离都不得充当道路可达时间。

购买候选按门店供给区分身份，保留 `product_id` 作为商品引用。可见期、排序、排除统计、呈现窗口、换新轮转和购买凭据均以 `supply_id` 区分；同商品不同门店不能互相覆盖或共享可见凭据。持有物品与消费仍按商品身份记录。

`supply_browsed_at` 与 `supply_browsed_location` 分别按供给保存呈现时刻与呈现地点。新呈现另一条供给不能延长旧供给的有效期；已看见供给集合与这两份记录的键必须一致。通用浏览活动完成时也只授权实际窗口，并在结果中保存该窗口。

单次模型观察共用一个供给呈现窗口：本次发现或浏览回灌的实际供给优先占用 `candidate_presentation_limit` 名额，当前事实保留这些供给发生变化后的比较行，其余候选只补剩余名额。回灌与当前事实重复的同一供给只占一个身份名额。可见凭据和呈现时刻只更新实际进入模型可见位置的身份，宿主 `data.supplies` 保存的已知供给集不等于本次呈现集，不能据此更新窗口外供给的凭据。

交互菜单继续按地点 `kind` 与人物声明求交集；新增发现工具必须贯穿允许工具闭集、实际模型 Schema、本地校验、环境重验和正式场景菜单。地图事实不被菜单隐藏，发现动作可以被菜单禁止。活动环境门只读取显式 `location_kinds`，覆盖候选、启动和恢复路径。

生活活动的目录声明必须为 `feedback_boundary=true`，复用既有反馈边界与实际暂停、继续、恢复控制。暂停保留已结算进度并释放当前活动占用，人物可随后出行；恢复时按人物当前地点重新验证原活动的显式环境要求，同时执行既有菜单、归属与能量条件。环境不满足时明确拒绝并保留暂停进度，不得把恢复门留成无法通过真实暂停进入的分支。验收必须经过真实引擎的启动、反馈、暂停、换地点和恢复请求，不能用辅助函数调用代替接线证明。

## 整单购买与履约

购买请求的每项为 `supply_id/quantity/price_version`，删除以商品身份直接选择卖方的请求格式。整单包含一至五项，必须为同一地点和同一卖方账户；同账户跨地点也必须拒绝。重复供给项不得绕过库存检查，应明确拒绝重复项。

整单逐供给重验后一次付款；任意一项失败时账户、所有门店库存、人物库存、订单和事件均不发生购买副作用。成功时只扣所选供给库存、只给其卖方记账。单件与多件订单使用同一个权威购买路径，删除重复旧购买实现。

自提要求人物已在所选门店，目的地也为该门店；付款与交付证据分别明确，即时自提不得额外检查配送路线。配送要求供给支持该方式、目的地在声明范围内且有已冻结可行运输路线；时长使用既有分时路线时长和供给处理时长。同单按最迟备货时刻一次配送。付款并不意味着人物已持有，只有交付时增加目的地商品库存；重复到期事件不重复增加库存。

交易结果和配送记录保存供给、商品、地点、卖方、实际报价版本、金额、路线和来源。已交付物品按商品合并，同一商品来自不同门店不能改变商品规格或消费效果。既有资金守恒、数量守恒、幂等、原子提交与错误分类继续适用。

## 记录、恢复与交付

当前窗口与本次查询或浏览回灌完全相同的供给比较行只在提示中呈现一次；报价、库存、营业或其他比较事实变化时保留当前事实和历史结果。当前事实可用 `supply_id/based_on_action_id/changes` 引用本次回灌中相同供给的完整行，未列字段继承该行，`changes` 按键替换，空值是值，嵌套对象整项替换；必须能无损还原当前公开行，不能丢掉报价变为未知等空值变化。没有本次历史行的供给仍用完整行。完整当前行保留在原始观察 `data.supplies`，动作结果保留历史完整证据。观察记录实际呈现的比较事实；发现结果记录实际查询条件与实际返回行，不能在导出时用当前目录重建历史。选择记录引用人物真正接触过的供给与报价。查询、旅行、购买、交付、使用仍是不同事实。

运行清单和导出清单保留地图版本、来源、许可及通知；逐条比较与交易可关联对应来源，场景假设不得标成真实门店事实。许可判断按来源和实际组合方式处理，不能仅以一个 share-alike 布尔值推断许可兼容。

世界结构版本更新，旧场景、旧购买请求和旧检查点直接拒绝。新建、打开、共同检查点恢复及分支都验证地图与代码身份；供给库存、报价、营业例外、可见供给和呈现轮转必须完整往返。地图或供给篡改拒绝，分支不能修改父目录。
