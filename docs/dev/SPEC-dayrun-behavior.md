> 来源：[行为提案](PROPOSAL-dayrun-behavior.md)；用户已授权确定细节、修订规格及完整实现。
> 本文定义特性行为和验收；接口归 [CONTRACTS](../CONTRACTS.md)，记录格式归

## 人物体验与范围

人物可以持续做事，同时进行按占用、目标、地点与出行方式准入的活动；
世界只记录实际经过的时间、接触的内容和消耗的食物。
人物自由表达感受和打算，这些文字始终是主观自述；已经发生什么，由已提交的环境事件证明。
正式场景提供真实可执行的餐馆餐食，通用地图允许空菜单并如实表达。

```mermaid
flowchart LR
    O[观察可用内容、餐食与活动] --> A[人物选择一项行动或一个活动组合]
    A --> C[按占用、目标、地点与出行方式校验，原子受理]
    C --> P[各活动独立推进]
    P --> B[同一人物共同时间只结算一次]
    B --> E[提交实际区间和结果]
    E --> F[已核验经历]
    F --> M[人物感受、打算和反思]
    E --> W[新事实才产生新的提醒]
    W --> O
```

本特性包含等待真实性、同人并行生命周期、餐馆进食路径、记忆事实约束和持续活动唤醒。
不增加自动替人物行动的计划执行器，不增加一次“在此用餐”动作，不做主观文本语义判别器。
不增加另一套模拟、播放、账本或记忆检索框架。旧单活动槽和被替换的记忆权威合同直接删除，
旧快照拒绝，不保留兼容字段、迁移或回退路径。

## 等待与内容接触

- 等待记录本人的实际开始、结束、状态与正时长区间。没有可核验等待对象时原因为空，
  不从人物自由解释、地点名称或某条未来事件推断等待目的。
- 等待只按真实清醒时间结算身体；删除等待隐含的被动娱乐缓解和
  “casually browsing”叙述。不能产生播放进度、内容接触、浏览次数或已完成的进食。
- 同时存在真实播放活动时，内容接触和娱乐效果只来自该播放的实际执行区间。
  等待不设人为占比上限，不为了填满时间线替人物选择内容。
- 导出分别报告等待实际秒数、原因未知的等待秒数、真实内容接触区间；人的经过时长取区间并集，
  活动各自的时长可以重叠，不能拿活动时长总和冒充一天长度。

### 真实音频来源与揭示

本次加入 `podcast_episode` 内容品类，使用 NASA 官方 Houston We Have a Podcast 的 Space Habitat，
冻结原始页中 00:01:52 至 00:14:58 的英文访谈选段，时长 786 秒。原始来源、节目身份、
官方音频 URL、原始时间锚点、派生时间轴与 SHA 都进入语料清单；不重抓现有无关来源。
使用现有 `watch` 播放活动和独立内容进度，不另建音频生命周期，也不把原视频改名成播客。

官方时间锚点标到段落，音频只在某段完整播放到官方下一锚点后揭示该段文字。
不能以相交为由提前揭示整段，不能估算词速伪造逐词时间。暂停、倍速、恢复和片段结束均遵循
真实媒体位置；实际人物提示明确为听取节目。该来源的使用与转载条件须随来源核验记录。

## 同一人物的活动集合

### 唯一状态与资源准入

`WorldState.activities` 是活动唯一事实源；删除 `AgentState.current_activity_id`，
按人物和状态稳定排序取得当前及暂停活动。观察提供完整活动集合，每项独立控制，
不选择一条“主活动”替代其他活动。世界结构版本提升，恢复时核对人物归属、资源、两个名额、准入事实、
目标和时间。

活动只占用它显式声明的个人资源。占用名取时间与能量规格第五章「并行准入」的七个：`idle`、`travel`、`eyes`、
`ears`、`hands`、`voice`、`work`。
活动声明、准入、恢复校验和人物工具必须使用同一套资源规则。
观察的 `occupied_resources` 保存当前活动声明的排序并集，供环境准入与动作条件说明使用，不剪裁可选动作
（时间与能量规格第五章）；它是可重建的只读投影，不另存世界资源槽。

| 活动 | 占用 |
| --- | --- |
| 等待 | `idle` |
| 睡眠 | `idle`、`travel`、`eyes`、`ears`、`hands`、`voice`、`work`（全部） |
| 步行 | `travel`、`idle` |
| 驾车 | `travel`、`idle`、`eyes`、`hands` |
| 工作 | `work`、`idle` |
| 视频、剧集、网文、段子等观看 | `eyes`、`ears` |
| 播客（`podcast_episode`） | `ears` |
| 游戏、读信、浏览 | `eyes`、`hands` |
| 食用或使用、生活活动 | `hands` |
| 交谈、通话 | `voice`、`ears` |

占用之外，准入另按下列事实判定：

| 准入事实 | 规则 |
| --- | --- |
| 实际地点 | 出行中人物的在场资格是「途中」；`agent.location_id` 保留出发地，作路线身份与菜单解析用；判定现场资格时同时检查进行中的出行 |
| 目标在场 | 办公室工作、当面交谈、现场制作与到店取得都要求人在目标地点；出发前须先结束或暂停所有进行中的活动，否则以 `ACTIVITY_PRECONDITION_UNMET` 拒绝并点名这些活动 |
| 出行方式 | 驾车途中，需要手动操作的瞬时动作（发消息、远程下单、提交成果）以 `ACTIVITY_PRECONDITION_UNMET` 拒绝；步行途中受理，远程下单的送达地与配送资格取出发地 |
| 物品状态 | `consume` 只接受此刻所在地点的已取得物品；途中没有可用的持有物；未交付的订单不可用 |

因此驾车与播客、通话（同一请求开始或途中开始，到达时一并结束），以及工作与食用、观看、播客的组合
都在实现和验收范围内。驾车与视频、游戏、浏览、食用、睡眠，两段观看、观看与游戏、交谈与通话、两条出行
以 `RESOURCE_CONFLICT` 拒绝；驾车与办公室工作、当面交谈、到店取得按目标在场拒绝；驾车时发消息、远程下单、
提交成果以 `ACTIVITY_PRECONDITION_UNMET` 拒绝。
暂停与终态不占资源，不同人物的个人资源互不排斥。原有地点、资格与持有量条件继续成立。
组合由资源交集判定，不能另写一个允许组合白名单或给某个目标临时放行。

### 人物入口与独立控制

- 人物通过 `start_activity` 提交等长的 `{targets, actions, ways}`。`actions` 逐项取 `travel`、`interact`、`obtain`、
  `consume`、`sleep` 五个动词之一；各对象与对应方式均为冻结观察中的可读短语；
  引擎的私有绑定定位实际活动、出行方式与报价。一次提交包含一至两个对象，双对象活动原子启动；
  不接受第三项、嵌套动作或内部编号。工作正文与消息正文分别由独立工具提交。
- 每项必须满足当前人物和地点的有效菜单、实际可见目标及原启动条件；组内和与既有 ACTIVE
  活动的资源都必须相容，开始后所占名额不超过两个，并满足准入事实。全组在暂存状态校验，
  任何失败整组拒绝，余额、库存、邀请、游戏状态、活动及事件草稿均不留部分成功；程序错误仍作为程序错误报告。
- 组合是一个幂等动作，公开结果列出独立活动的可读名称，内部证据保留活动身份。每个活动独立形成进度和终态，
  请求只有所有子活动终结后才形成聚合终态；第一项完成不能完成其他项或覆盖其终态。
  子活动终态先由自身进度快照记录；组合只产生一次动作聚合终态：全部完成为 completed，
  任一失败或截断为 failed，否则有取消则为 cancelled。未全部终结时请求保持 in_progress。
- 每轮决策提交一个世界请求，登记即结束，不再单独 `finish`。模型可以从真实动态工具入口选择组合，
  不能仅靠测试预置两个 ACTIVE 证明功能存在。
- 开始新活动不自动暂停旧活动。报告、暂停、结束只影响点名活动；未点名活动
  按既定计划继续。控制在人物实际获准决策时执行，不要求所有活动同处旧的反馈时刻。
- 暂停的活动只在开始地点恢复，恢复重验目标、占用与准入条件，能量不参与；失败保留原暂停进度。
  暂停期间不推进该活动。游戏动作由本轮可读对象与动作绑定，不能用普通继续越过回合。
  交谈和通话保留不可暂停、可结束合同；路上的活动不能暂停（`ACTIVITY_PAUSE_UNAVAILABLE`）。
- 内容先结束时只完成播放，出行继续。到达时出行与路上开始的活动同一秒结束（后者记 `route_ended`），成为待收尾；
  途中结束出行时，路上开始的活动同样记 `route_ended` 并成为待收尾。到达不重置内容，接着听不增加接触次数。
  同时结束各自留证，在一轮内一并收尾。实验截止分别截断所有未结束活动，截断不是完成。

### 共同时间与身体结算

- 人物保存 `body_settled_at`。活动开始、控制及世界事件均发生在已经结算的共同世界边界。
  下一边界必须考虑所有活动的结束、内容终点、游戏交互、身体阈值、计划提醒、餐时窗口起止、场景本地零点、
  环境事件和实验截止。
- 每个人在同一真实区间只扣一次基础代谢，只推进一次清醒或睡眠压力、睡眠不足及公共需求增长。
  时钟只在人人有进行中活动时推进，不产生空白区间。
- 零能量不限制任何活动；能量保持下界零，其余清醒体感照常变化。
- 并行集合的运动负荷取最大 MET，而非求和。这是明确的实验假设，不作为人类生理有效性结论。
  结算与阈值预测使用同一公式，按各活动结束点切分预测区间。
- 各活动独立效果按其真实 ACTIVE 秒数计算；同一身体通道先汇总再应用既有界限，
  不受活动身份排序影响。工作使用同一个公共身体前后状态；食物热量按实际食用量入账一次。
- 记录每人每区间唯一的共同身体结算，包含参与活动、区间、身体变化与资源流。
  共同结算使用 `environment_event.data.kind=body_settlement`，其顶层 activity_id 为空，
  data 包含 interval_start/end、activity_ids、body_settlement、resource_flows 及唯一的
  decision_offered/wake_reasons。各 `activity_progress` 用 body_settlement_event_id 引用它，
  只记录自身进度、activity_efficiency、消费和内容接触；
  不复制身体账，不把联合代谢成本任意归给某条活动。
- 所有进度都参与当日目标匹配；每个目标和活动仍遵守原来的首次推进、一次情绪脉冲规则。

## 餐馆的实际进食路径

- 三个正式场景选中的三家餐馆必须显式关联已存在的 `prepared-meal` 商品，各有可自提且初始
  有库存的餐食。门店与菜品的关联、报价和库存是场景假设，不能冒称真实门店菜单。
  最终选中地点、供给、商品和有效菜单的交叉覆盖由正式输入验收检查。
- 通用地图允许空菜单、售罄、闭店或购买条件不满足；不增加“每家餐馆永远有食物”的世界不变量。
  不解析自由目标文字来生成餐食，不凭地点名字放开资格。
- 真实到达后，从到达收尾那一秒起，观察通过现有候选窗口呈现本店可购供给，人物可直接购买已呈现项，
  不强制再发现一次。未进入窗口的供给不因同店、同商品或摘要而获得购买授权。
- 观察明确说明当前地点有无可购餐食；依据权威本地供给和当前购买条件，不能从有限窗口为空
  推断整家餐馆无食物。空菜单表达进入实际人物提示，遵守既有字符预算。
  饥饿为「饿」及以上时，该句改为吃饭途径句：按手边、在途、当地可买、可配送、附近能买的顺序说出第一条成立的途径，
  都没有时视浏览是否可用给出提示；只引用本轮观察的事实，不授权未呈现的供给（时间与能量规格第三章）。
- 自提沿用付款、扣门店库存和即时增加本地持有量；配送付款后仍等待真实交付事件。
  到达、付款、交付、开始消费都不能单独证明吃过；只有正消费区间证明实际吃了多少。
- 中断与恢复保留已付费用、供给库存、交付状态、剩余持有量和已吃份额，不重新付款、交付或吃
  已消费部分。到达后发现不可购不撤销真实行程，也不虚构另一家餐食。

## 已核验经历与人物自述

### 事件投影

记录引擎从本人已提交且不超过明确截止序号的事件生成 `verified_experiences`。
每条携带 kind、agent_id、activity_id、source_event_id、event_seq、occurred_at 及种类载荷。
观察 data.verified_experiences 只提供本人在当前 observation 事件之前已提交的最近五条，
按 event_seq 正序展示；本轮冻结 observation_event_id 绑定该窗口的截止。
带身份的结构行只留在私有观察；发给模型的是按同一窗口与顺序写成的句子，不含内部身份。
完整截止前缀用于离线投影与导出，不把完整历史复制到每轮观察。
模型没有写入口；动作请求、受理、自述及模型反思均不能生成已核验经历。

| 经历 | 来源与内容 |
| --- | --- |
| waited | 等待活动实际正时长区间；没有已核验原因时为空 |
| consumed | eat 的正实际消费增量，保留商品、地点、数量和区间；中途消费不称整餐完成 |
| arrived | 真实路线到达的已提交结果；保留实际地点、活动和到达时刻 |
| played | 真实播放的内容身份与正向媒体区间；等待、目录浏览或开始播放不算已播放 |

消费事件的 `interval_quantity` 必须为本区间增量，累计量另存 `cumulative_quantity`。
禁止把累计量冒充区间增量后重复求和。投影重复读取、暂停恢复及检查点分支均幂等，
不同人物不串记录；应存在而畸形的结算字段报错并记录日志，不猜测缺失事实。

### 主观记忆与巩固

- `conclude_activity.memories[i]` 对应 `task[i]`，合计零至八条；模型写入、记忆查询返回和反思的
  自由文字一律标明为人物自述，持久记录和工具结果均固定 epistemic_status=subjective。
  WorldMock 可写类型为 commitment、relationship、preference、goal、conflict、resolution、
  identity、routine、reflection；删除 event、observation 两种 WorldMock 输入。
  就寝反思同样写 reflection，不能从旁路恢复已删除类型。保留感受、打算、偏好、关系等
  表达；记忆不带引用，来源由系统登记。来源不证明自由文字为真。
- 已核验经历、人物自述在实际提示、检索、长期记忆和导出中明确分开。
  自由主观文字可能包含错误认识，但永远不能进入完成事实章节、结构化经历、客观指标或世界状态。
  不使用正则、提示词或另一模型假装能证明任意自由文字属实。
- 长期记忆由 WorldMock 确定性装配：身份取冻结画像，最近实际经历取事件投影，
  主观内容单列。模型只贡献主观归纳和反思，不能直接重写事实章节。
  已有检索、存储、阈值触发和共同检查点继续复用 AS2，以单一可覆写构造接点接入专用记忆运行时。
- 事实投影的完整来源由事件库保存，提示按既有预算显示近期事实；memory_* 仅检索主观 episodes，
  不新增另一事实检索入口。当前提示以本轮观察五条为唯一近期事实窗口，不重复拼入旧 MEMORY.md
  的事实窗口。
  `MEMORY.md` 是可重建视图，不能反过来当作世界事实来源。
  每步刷新该视图不得重置主观巩固计数。主观归纳结果在既有记忆状态中持久保存，仅在原有阈值
  或就寝触发时更新；刷新视图与标记主观巩固是两个明确操作。
- 就寝反思新增的身份必须进入该次记忆更新证据。零条新记忆合法，不能因空更新身份使运行失败。
  任何写盘失败不能报告成功更新；恢复保留事实、自述和来源身份的区别。
  更新证据区分新增与合并，合法合并旧身份不得被质量检查误报重复；空输入且视图未改变可不写
  memory_updated，视图或反思实际改变时必须写证据。

## 持续活动与必要唤醒

- 保留现有结算、重新考虑和唤醒的职责分离。静默边界推进全部活动，不调用人物决策模型、不提供决策、不生成观察、
  不写人物记忆；场景本地零点与启动路径由运行时后台任务 `plan_day` 生成当日计划，按时间与能量规格第四章留证。
  每个人每个边界首轮一次决策，理由包含全部新事实；没有进行中活动、有待收尾活动或业务拒绝之后，同一秒可再决策，
  受 `max_same_moment_decisions` 约束。
- 任务在截止前三十分钟、当前地点在闭店前十五分钟且威胁承诺时精确提醒。
  保存已实际交付给人物的当前威胁签名；相同条件持续成立不反复提醒。
- 任务签名绑定任务及其截止；营业签名绑定地点、本次闭店时刻及被威胁承诺。
  闭店威胁只由当前地点绑定的未完成任务证明。现有持续活动的启动和恢复不受营业时段限制，
  因此当前及暂停活动本身不构成闭店威胁；无结构化地点的当日目标和其他地点任务同样不构成。
  新任务、真实修改截止、新闭店边界或新增受威胁承诺形成新提醒；每次进度或剩余秒数不构成新签名。
  截止或营业变化指给定权威事实的变化，不增加运行中改期或营业管理接口；
  正式场景的新任务和后续营业区间沿既有事件与日历生效。
- `activity_infeasible` 保留名称，当前无来源。
- `commitment_threatened` 随具体新威胁出现，不是永久开关。预测下一边界和实际唤醒使用同一事实生成器，
  检查所有可见未完成任务，不能只检查最早的一项。
- 睡眠过滤掉且未实际提供的提醒不能提前消耗；醒来后仍成立的威胁可以提醒。
  消息、到达、完成、真实截止失约及正常重估仍独立生效，不能被预警去重吞掉。
- 威胁交付状态与身体时刻随共同检查点保存，恢复不重扣区间、不重复同一持续预警。
