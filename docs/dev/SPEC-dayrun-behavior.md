<a name="spec-dayrun-behavior-人物体验与范围"></a>
## 人物体验与范围

人物可以持续做事，同时进行按占用、目标、地点与出行方式准入的活动；
世界只记录实际经过的时间、接触的内容和消耗的食物。
人物自由表达感受和打算，这些文字始终是主观自述；已经发生什么，由已提交的环境事件证明。
正式场景提供真实可执行的餐馆餐食，通用地图允许空菜单并如实表达。

```mermaid
flowchart LR
    O[观察可用内容、餐食与活动] --> A[人物选择一项行动或一个活动组合]
    A --> C[按占用、目标、地点与出行方式校验，原子受理]
    C --> P[各活动独立推进]
    P --> B[同一人物共同时间只结算一次]
    B --> E[提交实际区间和结果]
    E --> F[已核验经历]
    F --> M[人物感受、打算和反思]
    E --> W[新事实才产生新的提醒]
    W --> O
```

本特性包含等待真实性、同人并行生命周期、餐馆进食路径、记忆事实约束和持续活动唤醒。
不增加自动替人物行动的计划执行器，不增加一次“在此用餐”动作，不做主观文本语义判别器。
不增加另一套模拟、播放、账本或记忆检索框架。旧单活动槽和被替换的记忆权威合同直接删除，
旧快照拒绝，不保留兼容字段、迁移或回退路径。

<a name="spec-dayrun-behavior-等待与内容接触"></a>
## 等待与内容接触

- 等待记录本人的实际开始、结束、状态与正时长区间。没有可核验等待对象时原因为空，
  不从人物自由解释、地点名称或某条未来事件推断等待目的。
- 等待只按真实清醒时间结算身体；删除等待隐含的被动娱乐缓解和自动消遣叙述。
  不能产生内容进度、内容接触次数或商品效果。
- 同时存在真实 `action` 活动时，内容接触和类别效果只来自该活动实际推进的内容区间。
  人物选择动作与可选 app，环境在该组合的绑定内容里抽取；等待既不抽取内容，也不消费推送。
  等待不设人为占比上限，不为了填满时间线替人物选择内容。
  系统层把“空档里照自己的习惯做别的事、等待只用于几分钟内就有决策机会的时候”作为平常人的过法写给人物
  （[让「等待」成为例外规格](SPEC-idle-fillers.md#spec-idle-fillers-让等待成为例外开发规格)）；环境仍不设占比上限、不替人物选择内容。
  2026-10-05 的用户裁决取代早先[一日运行行为设计](PROPOSAL-dayrun-behavior.md)采纳的“不预设等待越少越好”。
- 导出分别报告等待实际秒数、原因未知的等待秒数、真实内容接触区间；人的经过时长取区间并集，
  活动各自的时长可以重叠，不能拿活动时长总和冒充一天长度。


<a name="spec-dayrun-behavior-同一人物的活动集合"></a>
## 同一人物的活动集合

<a name="spec-dayrun-behavior-唯一状态与资源准入"></a>
### 唯一状态与资源准入

`WorldState.activities` 是活动唯一事实源；按人物和状态稳定排序取得当前及暂停活动。观察提供完整活动集合，每项独立控制，
不选择一条“主活动”替代其他活动。世界结构恢复时核对人物归属、资源、两个名额、准入事实、目标和时间。

占用闭集为 `wait`、`entertainment`、`work_study`、`exercise`、`daily_care`、`talk`、`travel`、`use_app` 八个。
数据集动作占自己的类别名额；`social` 使用 `talk`；`phone_continuous` 另占 `use_app`。睡眠占全部八个；驾车占
`travel`、`wait`、`entertainment`、`work_study`、`exercise`、`daily_care`、`use_app`，因此只能再与交谈类动作并行。
活动声明、准入、恢复校验和人物工具使用同一套注册表规则。`occupied_resources` 是当前活动占用的排序并集，只读派生，不另存资源槽。

| 活动 | 占用 |
| --- | --- |
| 等待 | `wait` |
| 睡眠 | 八个占用名 |
| 步行 | `travel` |
| 驾车 | `travel`、`wait`、四个非社交类别、`use_app` |
| 娱乐、工作学习、运动、日常照料动作 | 对应类别；方式为 `phone_continuous` 时另占 `use_app` |
| 社交动作 | `talk`；方式为 `phone_continuous` 时另占 `use_app` |

占用之外，准入另按下列事实判定：

| 准入事实 | 规则 |
| --- | --- |
| 实际地点 | 出行中人物的在场资格是「途中」；`agent.location_id` 保留出发地，现场资格同时检查进行中的出行 |
| 目标在场 | 场景分配的工作内容要求本人位于工作地点；当面社交要求双方同处；出发前须结束或暂停其他进行中活动 |
| 出行方式 | 驾车途中需要手动操作的瞬时请求以 `ACTIVITY_PRECONDITION_UNMET` 拒绝；步行途中照常按占用与地点判定 |
| 动作类别 | `exercise` 只在 `home`、`outdoor`、`fitness` 地点可开始；其余类别没有额外地点类限制 |
| app 与使用方式 | 有 app 的动作必须由人物显式选择该动作绑定的 app；没有 app 的动作必须写 null；方式由目录冻结 |
| 内容与工作分配 | 动作与所选 app 必须存在合格内容；场景分配的工作内容只供本人且只在工作地点消费，完成后不再选择 |
| 社交对方 | `social` 类动作必须写已知人物或联系人，其他类别不得写对方 |

因此驾车与社交动作，以及任意占用不相交且满足事实准入的两项活动，都在实现和验收范围内；占用相交时以
`RESOURCE_CONFLICT` 拒绝，目标或地点不满足时以对应业务原因拒绝。暂停与终态不占资源，不同人物的个人资源互不排斥。
购买、驿站领取与闹钟登记是零秒系统动作，不创建持续活动；付款、配送、待领取和收货由订单与事件保存。


<a name="spec-dayrun-behavior-人物入口与独立控制"></a>
### 人物入口与独立控制

- 人物通过 `start_activity.items[]` 提交一至两项 `{target, way, from, to}` 与请求级 `answering`、`prefer`，删除旧平行数组和 `actions`。
  目标与方式唯一确定内部动作；取得用 `from` 写可选门店或渠道约束，`to` 为 null 表示本人，其他收货人写已知人物名称；
  本人进食或使用的 `consume` 两端均为 `null`，给予通过「给予」方式独立解析并写来源、受赠人，其他动作两端为 `null`。
  取得给本人时 `to=null`；包含购买的请求 `prefer` 必须取「最快拿到」或「到手价最低」，其他请求必须为 null；`answering` 写所回应的直接消息。
  各对象与对应方式均为工具层中的可读名称（取得的商品可以指名本轮未列出的）；
  引擎的私有绑定定位实际活动、出行方式与报价。一次提交包含一至两个对象，双对象活动原子启动；
  不接受第三项、嵌套动作或内部编号。工作正文与消息正文分别由独立工具提交。
- 每项必须满足当前人物和地点的有效菜单、实际可见目标及原启动条件；组内和与既有 ACTIVE
  活动的资源都必须相容，开始后所占名额不超过两个，并满足准入事实。全组在暂存状态校验，
  任何失败整组拒绝，余额、库存、邀请、app 内容进度、活动及事件草稿均不留部分成功；程序错误仍作为程序错误报告。
- 组合是一个幂等动作，公开结果列出独立活动的可读名称，内部证据保留活动身份。每个活动独立形成进度和终态，
  请求只有所有子活动终结后才形成聚合终态；第一项完成不能完成其他项或覆盖其终态。
  子活动终态先由自身进度快照记录；组合只产生一次动作聚合终态：全部完成为 completed，
  任一失败或截断为 failed，否则有取消则为 cancelled。未全部终结时请求保持 in_progress。
- 每轮决策提交一个世界请求，登记即结束，不再单独 `finish`。模型可以从真实动态工具入口选择组合，
  不能仅靠测试预置两个 ACTIVE 证明功能存在。
- `recall_task_summary` 与 `query_world(name, way, category, from, available_only, offset)` 属于只读查询，可与记忆查询同批；
  `name`、`way`、`category`、`from` 四个筛选键必填可空且至少一个非 null，`available_only` 必填且为布尔（true 只留已确认此刻可执行的条目），`offset` 必填且为非负整数；
  `from` 与购买请求的 `from` 同一来源解析，类别复用现有品类名称，筛选在排序与切页之前施加，同冻结观察分页无重无漏（个人事务与工作安排规格第五章，原为四键，阶段 4 落地）。
  不登记世界请求、不结束决策、不推进时间、不计同刻轮数，调用所在模型回复仍计十六模型回合预算。
  世界查询返回 `{matches, total_count, next_offset}`，末页下一偏移为 null，`total_count` 为全部筛选交集后的完整匹配数，每项只省略 null 与空集合、不再逐项附完整请求候选（同规格 5.3、5.4，阶段 4 落地），
  只保留模型与 tool 交换证据，不写进度层 `events` 或人物记忆；
  最终回合和截断重试不开放任何只读查询。
  每次接口报错返回英文原因与完整位置数组 `items[].path`、合法 `allowed_values` 和 `expected`；
  非闭集合法值为 `[]`，候选为完整新请求 `{tool, arguments, note}`，不读取旧候选形状。
- 开始新活动不自动暂停旧活动。报告、暂停、结束只影响点名活动；未点名活动
  按既定计划继续。三个控制请求另带请求级 `errands`（个人事务的新增、更新、取消，可为 `[]`；个人事务与工作安排规格 2.2，阶段 2 落地）：
  事务变更不改变任何活动的状态，活动控制也不改变事务；事务变更与同一请求的活动状态转换同批校验、同一事务提交，
  请求被业务拒绝时事务变更一并不生效，任何一条事务变更不合法则整请求被拒、世界不变。控制在人物实际获准决策时执行，不要求所有活动同处旧的反馈时刻。
- 暂停的活动只在开始地点恢复，恢复重验目标、占用与准入条件，能量不参与；失败保留原暂停进度。
  `use_app` 暂停和每次结算先写回全局 `ContentProgress`；恢复保留 `content_id`，读取最新全局位置，
  不重抽、不消费、不增加完成轮数，也不再次释放推送。
  交谈和通话保留不可暂停、可结束合同；路上的活动不能暂停（`ACTIVITY_PAUSE_UNAVAILABLE`）。
- app 内容先结束时只更新全局进度并在剩余计划时长内抽取下一条，出行和 `use_app` 活动继续；
  到达时出行与路上开始的活动同一秒结束（后者记 `route_ended`），成为待收尾；
  途中结束出行时，路上开始的活动同样记 `route_ended` 并成为待收尾。到达不重置全局内容进度。
  同时结束各自留证，在一轮内一并收尾。实验截止分别截断所有未结束活动，截断不是完成。

<a name="spec-dayrun-behavior-共同时间与身体结算"></a>
### 共同时间与身体结算

- 人物保存 `body_settled_at`。活动开始、控制及世界事件均发生在已经结算的共同世界边界。
  下一边界必须考虑所有活动的结束、动作内容的 `next_interaction_at`、app 推送整点、闹钟、身体阈值、计划提醒、清醒人物个人事务的未提醒时刻
  （睡眠中的人物不计入，不形成静默边界；个人事务与工作安排规格 2.5，阶段 2 落地）、清醒人物的班次与休息时段起止
  （睡眠中的人物不计入，不形成静默边界；[让「等待」成为例外规格](SPEC-idle-fillers.md#spec-idle-fillers-让等待成为例外开发规格)）、
  餐时窗口起止、场景本地零点、环境事件和实验截止。
  娱乐内容完成是静默边界并在同一活动内接续；其他类别完成内容时活动结束。清醒人物收到匹配动作与 app 的推送时以
  `app_push` 获得决策机会，睡眠中推送保留在会话但不唤醒；闹钟到点以 `alarm_ring` 唤醒。
- 每个人在同一真实区间只扣一次基础代谢，只推进一次清醒或睡眠压力、睡眠不足及公共需求增长。
  时钟只在人人有进行中活动时推进，不产生空白区间。
- 零能量不限制任何活动；能量保持下界零，其余清醒体感照常变化。
- 并行集合的运动负荷取最大 MET，而非求和。这是明确的实验假设，不作为人类生理有效性结论。
  结算与阈值预测使用同一公式，按各活动结束点切分预测区间。
- 各动作按类别与真实 ACTIVE 秒数施加固定效果；同一身体通道先汇总再应用既有界限，不受活动身份排序影响。
  商品效果只在真实收货时瞬时施加，不属于区间活动结算。
- 记录每人每区间唯一的共同身体结算，包含参与活动、区间、身体变化与资源流。
  共同结算使用 `environment_event.data.kind=body_settlement`，其顶层 activity_id 为空，
  data 包含 interval_start/end、activity_ids、body_settlement、resource_flows 及唯一的
  decision_offered/wake_reasons。各 `activity_progress` 用 body_settlement_event_id 引用它，
  只记录自身进度、activity_efficiency 与内容接触；不复制身体账，不把联合代谢成本任意归给某条活动。
  社交账的清醒判定与共同秒数取本区间共同身体结算的 `activity_ids`，不在推进后重新推断。
- 所有进度都参与当日目标匹配；每个目标和活动仍遵守原来的首次推进、一次情绪脉冲规则。


<a name="spec-dayrun-behavior-餐馆的实际进食路径"></a>
## 餐馆的实际收货路径

到店购买在受理当秒结算给在店的收货人，商品不进入人物资产。付款、收货与食品效果由同一次提交留证；
直送订单在到期当秒结算给实际收货人。完整运输时长严格超过一天的订单到期时只进入家庭最近且由场景选中的驿站，
状态变为 `ready_for_pickup` 并推送本人；本人到该驿站执行领取后才结算。动作名称、模型文字或到达地点不能替代收货证据。

连续身体变化由时钟推进先结算至收货秒；到店购买在当前同刻受理。到店受理与配送到期共用 `worldmock.life.receipt.settle_receipt`，该函数只施加本次瞬时商品效果并取走本次资源分录。函数同时将订单从 `pending` 改为 `delivered`、写 `received_at`、施加效果并取走本次资源分录。到店在付款的同一次提交内收货，配送在 `delivery_arrival` 当秒收货，不看收货人在哪里或是否睡着。
食品的 `provided` 为类别热量乘件数，`applied` 为按当秒睡眠不足利用率与能量上限得到的实际能量增加，超出上限的部分丢失。
休闲用品每行降低娱乐需要 0.10（下限 0），日常用品每行施加情绪脉冲 0.05。没有商品持有、使用时长、份额、丢弃或装备能力。
本次食品 `food:intake` 分录与休闲用品 `goods:receipt` 分录在函数返回前立即取走，主体与时刻都是收货人和收货秒，缓冲为空；日常用品不写资源分录。状态变化与 `goods_received` 同一事务提交，事件的 `caused_by` 指向该提交中的真实购买结果或配送到期事件。
到站写一条 `pickup_ready` 足迹，不写 `receipt`、`goods_received` 或商品效果；领取本人在该站全部可取订单，每单恰好结算一次。
已交付订单再次到期或重复领取不写状态、效果或事件。联系人没有身体，收货只改变订单状态与 `received_at`，不写 `goods_received`。
配送保留付款人的到期事件与唤醒，清醒模拟收货人得到同一个到期原因，睡着的不唤醒；到店不唤醒任何人。


<a name="spec-dayrun-behavior-已核验经历与人物自述"></a>
## 已核验经历与人物自述

本人 goods_received 投影为 received{order_id, goods_id, category, quantity}，activity_id 为 null；付款、请求与自述都不能替代收货证据。

<a name="spec-dayrun-behavior-事件投影"></a>
### 事件投影

记录引擎从本人已提交且不超过明确截止序号的事件生成 `verified_experiences`。每条携带 `kind`、
`agent_id`、`activity_id`、`source_event_id`、`event_seq`、`occurred_at` 及种类载荷。观察中的私有证据只保留
当前 observation 之前本人最近五条并按 `event_seq` 正序排列；完整截止前缀用于离线导出，不复制进每轮提示。
模型、自述和反思都没有事实写入口。

| 经历 | 来源与内容 |
| --- | --- |
| `waited` | 等待活动的真实正时长区间；没有已核验原因时为空 |
| `received` | 本人的 `goods_received`，含订单、商品、类别与件数；付款或到站不能冒充收货 |
| `arrived` | 出行活动按 `trip_id`、实际路径和到达结算生成的地点事实 |
| `played` | 任一 `action` 活动的真实内容增量，含 `content_id`、可空 `app_id` 与前后位置；目录展示或零秒活动不算消费 |

离线导出另生成 `app-usage.jsonl`。每行以 `fact_kind` 区分 `app_use`、`app_touch`、`content_consumed`、
`push_delivered`、`push_opened`、`push_released`。`phone_continuous` 与 `other_device` 生成使用区间和逐条内容消费；
`offline_assisted` 只在动作开始与实际结束生成触点；没有 app 的动作不生成 app 行。打开推送由匹配动作与 app、带
`pinned_by_push_id` 的真实活动证明，释放由内容完成和对应 session 状态证明。手机信号投影归 LabelKit-DataSet，
只从认证的 `app-usage.jsonl` 与 `purchases.jsonl` 逐行加工。重复读取、暂停恢复与检查点分支保持幂等，畸形结算字段拒绝而不猜测。

<a name="spec-dayrun-behavior-主观记忆与巩固"></a>
### 主观记忆与巩固

- `conclude_activity` 每项的 `memories` 与 `views` 属于该项的 `activity_name`（一日运行保真规格第六章，原为 `memories[i]` 对应 `task[i]`），合计零至八条；模型写入、记忆查询返回和反思的
  自由文字一律标明为人物自述，持久记录和工具结果均固定 epistemic_status=subjective。
  WorldMock 可写类型为 commitment、relationship、preference、goal、conflict、resolution、
  identity、routine、reflection；删除 event、observation 两种 WorldMock 输入。
  就寝反思同样写 reflection，不能从旁路恢复已删除类型。保留感受、打算、偏好、关系等
  表达；记忆不带引用，来源由系统登记。来源不证明自由文字为真。
- relationship、preference 两类必须带 `subject`，其他类型的 `subject` 为 `null`；relationship 的 `subject` 须是已知人物。
  这两类只在人设层按对象原地更新（同一对象取事件顺序最后一条，存储仍只追加），不进记忆层；`subject` 写入 AS2 前去掉。
- 已核验经历、人物自述在实际提示（记忆层的 `settled` 与 `self_notes` 分列）、检索、长期记忆和导出中明确分开。
  自由主观文字可能包含错误认识，永远不能成为完成事实、结构化经历或客观指标的依据，也不能改变任何世界事实（余额、身体、订单、内容进度与验收）。
  当日目标、活动自述与个人事务的文字是人物记下的打算，随人物状态保存、只用于呈现，不是世界事实：个人事务办没办成只由环境按结算证据写入，
  文字不参与结算与完成判定（个人事务与工作安排规格 2.1，个人事务随该规格阶段 2 落地）。
  不使用正则、提示词或另一模型假装能证明任意自由文字属实。
- 长期记忆由 WorldMock 确定性装配：身份取冻结画像，最近实际经历取事件投影，
  主观内容单列。模型只贡献主观归纳和反思，不能直接重写事实章节。
  已有检索、存储和共同检查点继续复用 AS2，以单一可覆写构造接点接入专用记忆运行时；阈值巩固由该运行时
  自行判定，阈值沿用 AS2，就寝反思的条目不计（时间与能量规格第七章）；巩固摘要不进入人物决策提示。
- 事实投影的完整来源由事件库保存；提示中的近期事实只由记忆层给出：构建提示时由环境从已提交事件与世界状态派生，
  今天已结束的每个 session 一条（`earlier_today`），更早日期只留起源于该日且仍未了结的事项与归属该日的就寝反思
  （`earlier_days`），JSON 不超过 8000 字符（[人物 Prompt 规格](SPEC-life-realism.md#persona-prompt-七层请求)第三章）。
  这里的未了结事项仍指本人在途的订单与未回复的直接消息；人物记下的未完成个人事务不进记忆层、不占这一字符窗口，由待办层 `errands` 呈现，
  环境确认办成的在进度层留一条只写名称的记录（个人事务与工作安排规格 2.6，阶段 2 落地）。
  memory_* 仅检索主观 episodes，不新增另一事实检索入口。`MEMORY.md` 与主观归纳不再拼入人物决策提示。
  `MEMORY.md` 是可重建视图，不能反过来当作世界事实来源。
  每步刷新该视图不得重置主观巩固计数。主观归纳结果在既有记忆状态中持久保存，仅在原有阈值
  或就寝触发时更新；刷新视图与标记主观巩固是两个明确操作。
- 就寝反思新增的身份必须进入该次记忆更新证据。没有可反思的主观记忆时不调用模型，零条新记忆合法，不能因空更新身份使运行失败；
  有可反思的记忆时，洞见只经唯一严格工具 `submit_reflection` 提交（一至五条，每条引用本次输入的记忆身份），输出不合合同是协议违约：
  附回英文校验错误重试，首次之外至多三次，耗尽即运行故障，不写入任何洞见、不登记 `memory_updated`、不降级为空反思（个人事务与工作安排规格 1.1，阶段 1 落地）。
  任何写盘失败不能报告成功更新；恢复保留事实、自述和来源身份的区别。
  更新证据区分新增与合并，合法合并旧身份不得被质量检查误报重复；空输入且视图未改变可不写
  memory_updated，视图或反思实际改变时必须写证据。


<a name="spec-dayrun-behavior-持续活动与必要唤醒"></a>
## 持续活动与必要唤醒

工作通知在送达的同一事件批次使任务可知。任务输入必填 `appointment`，普通工作为 null，真实预约为 `{starts_at, reason}`，
两键必填，时刻带时区且原因非空。删除输入 `available_at`、`availability_kind`、`appointment_reason`。
场景编译内部 `RuntimeWorkTask.available_at`，普通取最早本人关联通知时刻，预约取 `starts_at`；
人物到达要求地点即可开始普通工作，预约提前可知但到真实开放时刻才生成 `task_available`。每项合同至少有一封关联通知，
每封非空 `related_task_id` 邮件必须引用存在的任务，收件人为该任务受派人物。最早预约通知不得晚于约定开始，
后续提醒可以晚于开始且不改变开放时刻。正式素材在通知前已经有效；无通知或逐封错配受派人物被加载拒绝，不按开放时刻补造知情。
邮件正文仍须阅读；契约元信息由已知任务目标公开，睡眠中过滤通知唤醒的规则保留。

- 保留现有结算、重新考虑和唤醒的职责分离。静默边界推进全部活动，不调用人物决策模型、不提供决策、不生成观察、
  不写人物记忆；场景本地零点与启动路径由运行时后台任务 `plan_day` 生成当日计划，按时间与能量规格第四章留证。
  每个人每个边界首轮一次决策，理由包含全部新事实；没有进行中活动、有待收尾活动或业务拒绝之后，同一秒可再决策，
  受 `max_same_moment_decisions` 约束。
- 任务在截止前三十分钟、当前地点在闭店前十五分钟且威胁承诺时精确提醒。
  保存已实际交付给人物的当前威胁签名；相同条件持续成立不反复提醒。
- 任务签名绑定任务及其截止；营业签名绑定地点、本次闭店时刻及被威胁承诺。
  闭店威胁只由当前地点绑定的未完成任务证明。现有持续活动的启动和恢复不受营业时段限制，
  因此当前及暂停活动本身不构成闭店威胁；无结构化地点的当日目标和其他地点任务同样不构成。
  新任务、真实修改截止、新闭店边界或新增受威胁承诺形成新提醒；每次进度或剩余秒数不构成新签名。
  截止或营业变化指给定权威事实的变化，不增加运行中改期或营业管理接口；
  正式场景的新任务和后续营业区间沿既有事件与日历生效。
- `activity_infeasible` 保留名称，当前无来源。
- `app_push` 在推送实际写入当前地点会话时只给清醒人物一次决策机会；使用中的 app 不被打断，
  睡眠中不唤醒，醒来后仍可在同一会话内看到。阶段 4 唤醒闭集为 25 个；三个工作原因到阶段 5 才删除并成为最终 22 个。
- `commitment_threatened` 随具体新威胁出现，不是永久开关。预测下一边界和实际唤醒使用同一事实生成器，
  检查所有可见未完成任务，不能只检查最早的一项。
- 睡眠过滤掉且未实际提供的提醒不能提前消耗；醒来后仍成立的威胁可以提醒。
  消息、到达、完成、真实截止失约及正常重估仍独立生效，不能被预警去重吞掉。
- 个人事务的提醒时刻到点时只提供一次决策机会并记一次，唤醒原因为 `errand_reminder_due`，不进入睡眠允许集合。
  清醒人物的未提醒时刻进入下一边界与下一次决策机会的候选，精确在该时刻到点，预测与唤醒共用同一事实生成器；
  睡眠中的人物不计入候选、不形成静默边界、不交付也不消耗，错过的提醒在醒来的那个边界交付。
  每个为清醒人物提供决策机会的边界把该人物全部已到点未提醒的事务一并交付：同一边界到期的多条事务合并为一次决策机会，`errand_reminder_due` 只计一次，
  每条事务各写一条 `errand_reminded` 事件；与该边界的其他原因（如 `plan_reminder_due`）按枚举顺序并列。
  提醒不改变事务状态，事务完成或取消后不再提醒，更新 `remind_time` 后重新计一次；已提醒时刻随共同检查点保存，恢复不重复提醒。
  未完成的个人事务不计入在手承诺，不构成 `commitment_threatened`，不改变重估间隔与闭店预警（个人事务与工作安排规格 2.5，阶段 2 落地）。
- 声明了工作安排的人物，班次与休息时段的起止各提供一次决策机会，唤醒原因为 `shift_start`、`shift_end`、`break_start`、`break_end`，
  四个成员不进入睡眠允许集合（[让「等待」成为例外规格](SPEC-idle-fillers.md#spec-idle-fillers-让等待成为例外开发规格)）。
  清醒人物的起止时刻进入下一边界与下一次决策机会的候选，精确在该时刻到点，预测与唤醒共用同一事实生成器；
  睡眠中的人物不计入候选、不形成静默边界、不被叫醒，睡过的起止醒来后不补。起止由场景工作安排与世界时钟直接求值，不保存交付状态：
  检查点恢复与反事实重演后照常求值，已判定而尚未决策的原因随人物状态的 `pending_wake_reasons` 恢复，不重复、不补发。
  持续活动不因此结束、暂停或重排，起止不写事件。运行第一秒恰在起止上时只记 `run_start`。
- 威胁交付状态与身体时刻随共同检查点保存，恢复不重扣区间、不重复同一持续预警。
