# 裁决记录：人物卡片由数据集直接填写

> 日期：2026-10-11。规格冻结之后由所有者作出，随集成分支 `feat/environment-contract-revision` 一起合入。
> 本记录只写这一条裁决。冻结的[规格](SPEC-environment-contract-revision.md)和[提案](PROPOSAL-environment-contract-revision.md)不回写；
> 两者与本记录不一致的地方以本记录为准。
> 证据层级：读代码和离线套件。没有调用模型，没有做过真实运行。

<a name="ruling-persona-card-所有者的原话"></a>
## 所有者的原话

所有者看到「声明的作息与模型读出的时间冲突时保留卡片值并警告」「成对关系六条」这一套之后说：

> 唉 搞这么复杂干嘛 不要给数据集兜底，把检查去掉吧；系统实际要使用的字段改成必填，也不要什么模型去读故事

被告知今天是模型把 `background_story` 读三遍来填人物卡片之后说：

> 这不就是脱裤子放屁吗，你直接把这个表的格式拿出来让数据集填不就完了吗

<a name="ruling-persona-card-规格和提案原来怎么写"></a>
## 规格和提案原来怎么写

规格「人设作息窗口」一章、「版本、身份与基线」里人物卡片的几行，以及「实施顺序与验收」里身体与作息阶段讲作息的部分，原来的安排是：

| 事项 | 原来的写法 |
| --- | --- |
| 卡片从哪来 | 运行开始时模型读 `background_story` 三次，逐字段取共识；没读到的时间用引擎自带的缺省值补上 |
| 社交需要增长 | 模型给人物打大五分数，外向性换算成每小时增长 |
| 作者写的作息 | 七项可选；写了就原样盖进卡片，盖不进去时保留模型读出的值并记 `CARD_FIELD_CONFLICT` |
| 加载检查 | 时段要在 0 到 24（就寝到 30）之内、跨度不超过 12 小时；六条成对关系；卡片再检查时间先后 |
| 给作者的工具 | `worldmock profile compile`、`check`、`validate` 三个命令，用来看模型读出了什么、覆盖了多少 |
| 版本 | `persona.toml` 的 `schema_version` 保持 1，编译产物结构号升到 5 |

<a name="ruling-persona-card-现在适用什么"></a>
## 现在适用什么

| 事项 | 现在的做法 |
| --- | --- |
| 卡片从哪来 | 数据集作者在 `persona.toml` 里按表直接填：身份、当前处境、关系、习惯、口味、应对方式、作息。引擎逐字段照搬，不调用模型，不补缺省值，不改写任何数 |
| 社交需要增长 | 作者直接填 `social_need_growth_per_hour`，0.02 到 0.10；大五分数整个删除 |
| 必填 | 系统实际要用的字段都必填：睡眠中点、每日睡眠需要、起床、出门、午饭、晚饭、就寝五个时段、社交需要增长、身份、当前处境、关系、习惯、口味、应对方式。下班、到家两个时段可以不写，不写就是没有固定时刻，与工作安排没有任何联动 |
| 检查 | 只留表的格式和计算要用的：类型、必填、联系渠道的闭集、公式需要的数值范围、提示预算依赖的条数和字数上限；每个时段只要求是两个有限数且起点小于终点 |
| 删掉的检查 | 六条成对关系、0 到 24 与 30 小时上界、12 小时跨度、越过午夜的平移、卡片的时间先后、下班到家的先后、取整。`[5.0, 7.0]` 的就寝、早于晚饭的就寝、写成 25 点以后的下班都能加载，人物看到的就是作者写的时刻 |
| 删掉的东西 | 读故事的三次抽取与共识、缺省补齐、大五与映射表、声明覆盖与两个 `CARD_FIELD_` 警告、覆盖率报告、编译产物及其结构号和提示版本、三个 `worldmock profile` 命令、运行开始时为人物发的模型请求、`[model]` 里只给抽取用的 `persona_validation_max_retries` |
| `background_story` | 仍是必填的文字，零点计划照旧原样读它；只为抽取服务的一百字符下限删除 |
| 恢复 | 只留一条核对：恢复出来的卡片必须等于用冻结的 `persona.toml` 重新构造出的卡片 |
| 版本 | `persona.toml` 的 `schema_version` 升到 2，写 1 的文件被直接拒绝，没有读取旧格式的分支。人物工作区里的结构化卡片形状不变，所以 `AGENT.json` 的结构号不变。运行清单和质量报告的结构号不变 |

各处读到同一个值：人设层、卡片文本、零点计划、身体（饭点、困意、欠觉、社交需要增长）和评估（下班、到家偏离）读的都是 `persona.toml` 里的数。
原来「声明和模型读出的时间冲突」这个唯一例外随模型抽取一起消失。

<a name="ruling-persona-card-写这条裁决时定下的细节"></a>
## 写这条裁决时定下的细节

裁决没有写到、实现必须定下的点：

| 事项 | 定下的做法 |
| --- | --- |
| 饭点对身体的作用 | 钟面时刻落在午饭或晚饭时段里时饥饿体感加 0.15。时段按钟面读，写成 25 到 26 的午饭就是 01:00 到 02:00；这个算法对任何「两个有限数、起点小于终点」的时段都算得出来，所以饭点时段原来的 0 到 24 检查和「午饭晚饭不重叠」检查一并删除，重叠时也只加一次 |
| 联系渠道 | 只能写「电话」「微信」「见面」，每个关系一到三个。这三个词原来只写在抽取提示里，现在是加载时检查的闭集 |
| 没有关系或习惯的人物 | `relationships`、`habits` 必须写出来，可以是空数组 |
| 口味里重复的词 | 原样保留，不再替作者去重 |
| 给作者的拒绝原因 | 每条都先写出错的字段，例如 `identity.age is required`、`lunch_window: must be two finite hours with start < end`；缺了哪个必填字段一看就知道 |
| 运行输入警告 | 警告机制保留，因为还有两种与卡片编译无关的警告：没有任何 app 绑定内容而人物写了媒体口味，地点显示名带坐标或标识。随抽取和覆盖率删除的四种警告码一并从闭集里去掉 |
| 运行清单 | 少了 `world_dynamics` 一项（它原来保存由大五换算出的社交需要增长），结构号按上表不变；这个值现在在冻结的 `persona.toml` 里 |
| 评估读什么 | 下班、到家窗口直接读 `persona.toml`，不再从人物工作区取卡片 |
| 夹具人物 | 测试夹具的 `persona.toml` 写成完整的表，取值就是此前离线测试手工准备的那张卡片，人设层和以前一样；午饭、晚饭、就寝现在必填，所以夹具人物从此有饭点加成，零点计划里也多出这三个时段 |

<a name="ruling-persona-card-对基线的影响"></a>
## 对基线的影响

夹具的 `persona.toml` 改了，`persona_sha256` 随之变化；规格「版本、身份与基线」里写的「`persona_sha256` 不变」不再成立。
两份完整日基线和录制样例 `viewer-context.json` 仍只在修订末尾重做一次，本裁决的改动不单独重冻。
规格「核对升号次数」里「人物卡片 4 变 5」一项改为：编译产物的结构号随编译产物一起删除，`persona.toml` 的 `schema_version` 1 变 2。
