## 目标与依据

设计正文是每条规则唯一的家（`AGENTS.md`「文档维护」：接口和行为先改所属模块正文，再改实现）。本规格的设计正文与手册改动随规格同一次提交落笔，
代码由各轨道在此之后照着实现；所以这些文件在规格提交之后、代码合入之前写的是改后的行为。本章是那次改动的清单：每份文件改了哪里、依据哪一章，
以及逐一核对过、不用改的地方。系统层的规则原文不抄进设计正文，设计正文只转述话题；逐字原文只在代码和逐字用例里。

`docs/dev/` 下的历史记录（包括环境数据集合同里被本规格推翻的「非系列内容完成后停止……」「自动接续不由 pushable……决定」两句、零点计划「不读：身体数值、交互对象……」一句）
冻结不改；推翻它们的是本规格，现行规则以设计正文为准。`README.md`、`AGENTS.md` 与 `docs/INDEX.md` 只做简介和导航，核对过，不用改。

- 00 术语表「app 推送」「内容」（:96、:99）：推送状态不变；「时长决定执行时间」按每条仍成立。

- 02 :24「低于 800 千卡饥饿」：这是身体配置的紧急阈值，不是锚定热量，本次不碰。
- 02「放松与社交需要」（:53 起）：每条各按自己的缓解档位结算，与「条与条之间是结算边界」一致。

- 03 规则版本的加载与拒绝（:58–59、:102、:115）：只说「当前规则版本」，不写数字。
- 03「目录发布」（:302）：`refresh_manifest_identity` 原样保留 `rules_version`；样例环境的清单由版本提交改号，数据集清单由数据集重新发布。

- 04 槽位组合表「出行 + 用内容 app」（:77）：开车时用 app 维持现状。
