# AgentSociety2 设计文档改进指南

本文档说明如何按照 AGENTS.md 工程原则改进 `agentsociety2-design.md`，消除表格隐式引用问题。

## 评估结论

原文档在图形化、表格化、术语一致性方面做得很好，主要问题是**表格隐式引用**：
- 长表格创建了"需要跳转查找的索引关系"
- 后续章节引用表格内容时，读者需要回查才能理解
- 虽然没有显式编号，但实际阅读体验违背了"禁止编号指代"原则的精神

## 改进原则

### 原则1：表格引用时重述关键信息

**问题示例**（line 762-783 验证矩阵）：
```markdown
| 验收事项 | 必须覆盖的案例 | 实际验证入口 |
| --- | --- | --- |
| AS2 接入 | 真实注册、实例化... | `tests/integration`、AS2 `tests/test_direct_router.py` |
| 时间一致 | 更早结束、多人睡眠... | `test_engine_feedback.py`、`test_activities.py` |
...
```

后续引用时说"按验证矩阵执行测试" → 读者需要回查表格。

**改进方法**：
```markdown
## 验证矩阵

本设计定义了以下验收事项，每项都说明了必须覆盖的案例和实际验证方法。

### AS2 接入验收
- **必须覆盖**：真实注册、实例化、工具 Schema、人物观察和动作调用
- **验证入口**：`tests/integration` 目录的集成测试、AS2 上游的 `tests/test_direct_router.py`、真实短窗口运行
- **验收标准**：真实 AS2 环境能够发现并加载 LifeEnv，工具 Schema 正确生成

### 时间一致验收
- **必须覆盖**：更早结束时刻、多人睡眠、同秒事件、媒体倍速、实验截断
- **验证入口**：`test_engine_feedback.py` 测试活动反馈边界、`test_activities.py` 测试活动时间计算、AS2 的 `test_society_decision_round.py` 测试决策轮
- **验收标准**：所有时间推进场景下事件时间严格递增，活动结束时刻不被跨过

...（每个验收事项都完整说明）

## 后续引用方式

当需要引用验收标准时，这样写：

"AS2 接入的验收需要在真实 AS2 环境中加载 LifeEnv，通过集成测试和短窗口运行验证工具 Schema 的正确性。"

而不是："按验证矩阵的 AS2 接入部分执行。"
```

### 原则2：表格行自包含关键信息

**问题示例**（line 912-937 文件职责）：
```markdown
| 路径 | 新实现或修改的职责 |
| --- | --- |
| `src/worldmock/life/body.py` | 身体转换规则 |
| `src/worldmock/life/activities.py` | 全部生活活动 |
```

后续说"body.py 负责身体规则" → 如果读者忘了，需要回查表格。

**改进方法**：
```markdown
## 实现文件组织

本设计的实现按职责分布在以下文件中，每个文件都有明确的边界。

### 核心生活逻辑文件

**身体状态文件 `src/worldmock/life/body.py`**
- 职责：实现身体转换规则，包括能量消耗、睡眠恢复、效率曲线计算
- 依赖：场景定义的身体参数、活动额外消耗
- 测试：`tests/life/test_body.py` 覆盖基础消耗、睡眠恢复、效率曲线

**活动管理文件 `src/worldmock/life/activities.py`**
- 职责：实现全部生活活动的启动、推进、暂停、恢复、结束逻辑
- 依赖：身体状态、内容目录、地点规则
- 测试：`tests/life/test_activities.py` 覆盖每种活动的生命周期

...（每个文件都完整说明职责、依赖、测试）

## 后续引用方式

当需要引用文件时，这样写：

"身体状态的转换规则在 `body.py` 中实现，该文件负责能量消耗、睡眠恢复和效率曲线计算。"

而不是："见文件职责表的 body.py 行。"
```

### 原则3：首次引入概念时给出完整解释

**问题示例**（line 1066）：
```markdown
每个 LabelKit 输入窗口声明起止、知识截止、活动身份、边界类型与必要前置状态
```

假设读者已经知道"输入窗口"是什么。

**改进方法**：
```markdown
### LabelKit 输入窗口的定义

**输入窗口是什么** - 输入窗口是 LabelKit 加工的基本单位，代表一段连续的人物经历，
包含该段时间内的所有观察、决策和动作事件。每个窗口都是自包含的：它携带了模型需要的
全部上下文，不依赖其他窗口的信息。

**窗口的必要字段** - 每个输入窗口必须声明：
- **起止时间**：窗口覆盖的模拟时间范围
- **知识截止**：模型可以看到的信息的时间边界（通常等于窗口结束时间）
- **活动身份**：窗口内涉及的活动标识，用于追溯到原始事件
- **边界类型**：窗口结束的原因（活动完成、容量截断、实验结束等）
- **必要前置状态**：模型理解当前窗口需要的前置信息（如当前位置、持有物）

**窗口与原始事件的关系** - 输入窗口是原始事件的投影：它从完整的数字足迹中
选取一个时间范围，提取该范围内人物实际看到的信息，组装成模型可以处理的格式。
原始事件保持不变，一个事件可以出现在多个窗口中。

## 后续引用方式

当提到输入窗口时，可以说：

"每个输入窗口（即 LabelKit 加工的自包含经历片段）必须声明起止时间和知识截止..."

首次提到后，后续可以直接用"输入窗口"，读者已经有了完整理解。
```

## 具体改进位置

### 高优先级改进（严重影响可读性）

1. **验证矩阵表格**（line 762-783）
   - 问题：15+ 行表格，后续多处引用
   - 改进：拆成独立小节，每个验收事项完整说明

2. **文件职责表格**（line 912-937）
   - 问题：25+ 行路径映射表
   - 改进：按模块分组，每组完整说明职责、依赖、测试

3. **AS2 改动清单表格**（line 113-128）
   - 问题：表格列出改动点，但每点的"为什么需要改"不清楚
   - 改进：每个改动点单独成段，说明现状、问题、改动、验证

### 中优先级改进（影响跳转体验）

4. **LabelKit 输入结构**（line 606-638）
   - 问题：给出示例 JSON 但没有先解释字段含义
   - 改进：先解释字段，再给示例

5. **实验绑定表格**（line 826-838）
   - 问题：多项配置，后续引用时需要回查
   - 改进：分组说明（模型配置、依赖版本、数据身份）

6. **最终门禁表格**（line 1233-1248）
   - 问题：门禁条件很关键，但以表格形式容易被忽略
   - 改进：每个门禁单独成段，说明检查内容、通过条件、失败后果

### 低优先级改进（不影响理解，但可以更好）

7. **来源与接入行为表格**（line 396-408）
   - 当前已经比较好，每行都有完整信息
   - 可选改进：增加"为什么选这个来源"的说明

8. **事件类型枚举**（line 863-867）
   - 当前是连续文本列举
   - 可选改进：改为列表，每项说明触发条件

## 改进示例对比

### 改进前（原文档 line 762）

```markdown
| 验收事项 | 必须覆盖的案例 | 实际验证入口 |
| --- | --- | --- |
| AS2 接入 | 真实注册、实例化、工具 Schema | tests/integration、AS2 tests/test_direct_router.py |
```

后续引用："按验证矩阵执行测试。"

### 改进后

```markdown
## AS2 接入的验收方法

**验收目标**：确保 LifeEnv 能够被 AS2 正确发现、加载和调用。

**必须覆盖的测试场景**：
- 真实 AS2 环境注册：LifeEnv 类能被 AS2 的环境扫描器发现
- 正确实例化：传入场景路径后能够成功初始化世界状态
- 工具 Schema 生成：所有人物工具的 Schema 正确生成并符合 Pydantic 合同
- 人物观察调用：人物能够通过 observe 接口获取当前状态
- 动作调用：人物的动作请求能够正确到达环境并返回结果

**验证入口**：
- `tests/integration/` 目录下的集成测试覆盖完整的 AS2 初始化流程
- AS2 上游的 `tests/test_direct_router.py` 验证路由器的直接调用
- 真实短窗口运行（24小时双人场景）验证端到端能力

**通过标准**：所有测试通过，且短窗口运行能够产生完整的数字足迹。
```

后续引用："AS2 接入的验收通过集成测试和短窗口运行，确保环境能被正确发现、加载和调用。"

## 总体改进策略

1. **识别长表格**（>10 行）→ 拆成独立小节，每项完整说明
2. **识别引用点** → 在引用处重述关键信息，不要求读者回查
3. **识别新概念** → 首次出现时给出完整定义和上下文
4. **保持图表** → mermaid 图和短表格（<10 行）保持不变，它们没有问题

## 实施建议

**分阶段改进**：
1. 先改高优先级的 3 处（验证矩阵、文件职责、AS2 改动）
2. 验证改进后的可读性
3. 再改中优先级的 3 处
4. 低优先级的可以保持原样或最后改进

**改进原则**：
- 内容完全不变，只改组织方式
- 每次改进后检查引用点，确保不需要跳转
- 如果一个表格被引用 >3 次，优先改进它
