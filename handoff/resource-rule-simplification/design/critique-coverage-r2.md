## 阻断发现

### 暂停活动与跨 app 共享内容进度没有唯一合并规则

**观察事实**

- 规格第 534 行规定“暂停的不算”并发名额，第 491 行只禁止两项正在进行的 app 使用，因此 app A 暂停后，app B 可以开始使用同一跨 app 内容。
- 第 488–489 行同时规定：暂停保留当前内容、恢复不重抽；活动以自己的 `media_position_seconds` 推进；全局 `content_progress[content_id]` 跨 app 共享；完成时全局 `completed_rounds += 1` 并把位置归零。
- 第 552、554 行分别保存全局 `ContentProgress` 和活动内的 `start_position_seconds`、`media_position_seconds` 语义，却没有规定恢复时两者谁是权威，也没有活动所处轮次的快照。
- T34 只覆盖“结束一个活动后换 app 续播”，T35 只覆盖“同一活动暂停后原样恢复”；两者都没有覆盖“暂停 A → B 推进或完成 → 恢复 A”。现有三个相关变异只覆盖按 app 分库存储、看完后排除、恢复时重抽，没有覆盖陈旧位置回写或重复完成。

**可复现的规范反例**

app A 把内容甲从 0 播到 1000 秒后暂停。app B 从全局 1000 秒继续到 1500 秒，或者直接播完使 `completed_rounds` 从 0 变成 1、位置归零。恢复 app A 时，按“暂停保留”的局部位置可从 1000 秒继续；按“跨 app 共享进度”则应从全局 1500 秒或下一轮的 0 秒继续。前一种实现会把 1500 秒回退为旧值，或在同一轮已经由 B 完成后再次增加 `completed_rounds`；后一种实现会丢弃 A 的旧局部位置。两种实现都能逐字声称遵守现文。

**必须二选一的规则方向**

| 规则方向 | 明确规则 | 后果 |
| --- | --- | --- |
| 共享进度为权威（建议） | 暂停或任何结算先写全局；恢复保留 `content_id`、不重抽，但从最新 `ContentProgress.position_seconds` 重建活动位置。若别的 app 已完成该轮，则恢复从全局的 0 秒开始下一轮，恢复动作本身不增加 `completed_rounds`；只有把当前全局轮次实际推进到结尾的活动增加一次 | 保留 D-9 的跨 app 共享进度与“没有排除集合”；“暂停保留”解释为保留内容身份，而非冻结旧游标。无需新增轮次字段 |
| 暂停活动游标为权威 | 恢复必须从 A 的旧位置继续。要避免 B 的写入被覆盖或同一轮重复完成，就必须在暂停期间保留该内容轮次，禁止别的 app 抽到它；或者新增轮次版本并做条件合并 | 内容保留会引入 D-9 明确不要的排除集合；轮次版本会扩大 `ActivityState` 与合并协议，并使单一共享进度变成多个活动游标。两种代价都需要新的裁决与测试 |

**最小修复**

选择其中一个方向，并在生命周期、状态表、T34/T35 与变异表同一修改中落地。若采用建议方向，至少加入“B 只推进一部分后 A 恢复从最新位置继续”和“B 完成后 A 恢复从下一轮 0 秒开始，恢复不增加轮次，随后真实完成只增加一次”两个用例；加入“恢复读取陈旧活动位置”和“陈旧活动重复增加轮次”两个生产变异。

### B-30 与生命周期段给出了两个不同的随机种子算法

**观察事实**

- B-30（第 283 行）固定了唯一算法：UTF-8 材料的 SHA-256 摘要前八字节，以大端无符号整数初始化 `random.Random`，候选排序后用 `randrange`。
- 生命周期第 488 行仍以 `sha256(f"{random_state}:…")` 描述打开和接续；推送第 492 行更直接写成 `random.Random(sha256(f"{random_state}:{scheduled_id}"))`。这不是 B-30 的 Python 表达。
- 在本工作树要求的 CPython 3.12.13 上，以材料 `0:action-1:app-1` 探测：B-30 的首抽为 `693527`，把完整 digest bytes 当种子的首抽为 `463488`，把 hash 对象直接传给 `random.Random` 则抛 `TypeError`。
- T38 虽逐项声称核对 B-30，但阶段 4 的两个随机变异只改“推进 `random_state`”和“提交后才弹出事件”，没有改变摘要截取、端序或种子类型的变异来证明测试真正钉住算法。

**影响**

实现者按 B-30 与按生命周期段会得到不同内容、推送、`push_id` 序列和完整日基线；这不是文字简写，因为现文使用了可执行的 `random.Random(...)` 形式。

**最小修复**

生命周期与推送段不再重复种子表达式，只写“按 B-30，以打开键／接续键／`scheduled_id` 构造同一个随机流”。T38 增加一个生产变异，把“摘要前八字节大端整数”改成“完整 digest bytes”（或小端整数），并要求 T38 杀死它。
