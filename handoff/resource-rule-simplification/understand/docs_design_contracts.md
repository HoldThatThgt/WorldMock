Subsystem scope: the documents that currently *fix* the behaviours the proposal replaces (design chapters, contracts, specs, manuals, verification, experiment, status, index, README) and the machine gates that police those documents (`scripts/documentation_gate.py`, `documentation_refs.py`, `documentation_owners.py`, `scripts/build_design_doc.py`, their tests and fixtures).

Classification used below: **DELETE** = the whole section describes a retired mechanism and has no replacement rule; **REWRITE** = the anchor and heading stay, the body is rewritten in place (house rule: 原位改写); **KEEP** = unaffected or only touched by a version/identity sentence; **ADD** = new section the spec must create.

### 5.0 House rules every rewrite must obey (from `docs/dev/SPEC-idle-fillers.md#spec-idle-fillers-现行文档原位改写`, ruling R8/R9, `docs/design/README.md#readme-更新约定`, `docs/dev/SPEC-layering-and-test-tiers.md#layering-documents`/`#layering-archive`, `docs/INDEX.md#index-状态与变更约定`)

2. File header: each affected current document (design chapters, specs, CONTRACTS, EXPERIMENT, VERIFICATION) gets exactly one header line for the feature, written at the first stage that touches it and extended with section names and stage numbers later: `> **<特性名>修订**：按[<规格名>](<relative path>#<title anchor>)修订「<节名>」（阶段 N）` (查看器对象名称 and LabelKit specs append a clause to the status line instead); documents with a `日期` line update it. 3. Version table: one row per document per rewriting stage, appended as the **last row inside the table** (merge any rows separated by blank lines in the same batch — `00-overview.md` has one such gap); row id `` `<write-date>-<feature>-<stage>` ``, date column = write date; `docs/dev/ANALYSIS-spec-coverage.md` uses its two-column form; `docs/design/08-configuration.md` has four columns with author `Claude`; design chapters other than 05 bump the header `版本` minor once per feature at the first touching stage and only change the date afterwards; `05-recording-engine.md` adds a feature-identifier row and keeps `v1.6`.
