# Subsystem map: Map, locations, routes, travel time, trajectories

Worktree read: `D:/code/WorldMock/.claude/worktrees/rrs` (read-only). Baseline per proposal: `7e1ffab`.
Proposal: `docs/dev/PROPOSAL_2026-10-06_RESOURCE_AND_RULE_SIMPLIFICATION.md`; evidence: `docs/dev/research/resource-rule-simplification/{engine,dataset,industry}-evidence.md`.

Two facts that shape everything below:

1. **The engine-side tests of travel/delivery/wayfinding run against the published environment, not the in-repo fixture.** `tests/fixtures/environment/` is "一个虚构住处，空路线集合，空门店供给集合" (one location `home`, `routes: []`, `supplies: []`, README line 10). Tests that need `office`/`market`/`poi-…` and driving routes (`test_travel_cost`, `test_travel_time`, `test_travel_trajectory`, `test_browse_and_hints`, `test_storefront_commerce`, `test_dayrun_restaurants`, `test_location_sessions` travel cases, `test_input_warnings` map cases, …) only pass with `--environment-root ../WorldMock-Dataset/environment/zhangjiang-baseline` (`docs/manual/runtime.md:60-74`, `docs/dev/SPEC-environment-data-ownership.md:44`). At this checkout `D:/code/WorldMock-Dataset` has no `environment/zhangjiang-baseline`; its maps live under `requests/0001-white-collar-lianqiu/corpora/qingpu-lianqiu-map/` and `requests/0002-business-sales-zhaoming/corpora/business-map/` (observed, not modified). The spec must therefore plan the fixture upgrade (artificial graph with ≥3 nodes) at the same time as the production format switch, otherwise the new travel tests have nowhere to run.
2. **`sample_location_track` (the only GPS-trajectory producer) has no production caller.** `rg sample_location_track|LocationTrackRequest src custom scripts` hits only `src/worldmock/life/travel.py` itself; it is exercised solely by `tests/life/test_travel_trajectory.py` and `tests/life/test_domain_branch_coverage.py::test_location_track_rejects_broken_geometry_and_paths`. No `environment_event(kind=location_track)` is ever emitted by a run; no footprint export, LabelKit window or viewer reads `position_lonlat`. Deleting it is a pure removal.

## 3. Current formats and fixtures

### 3.1 Map files (frozen corpus, `schema_version: 3`)
- `dataset.json` — `MapDatasetDeclaration`: `schema_version:3, dataset_id, version, random_seed (StrictInt), category_assignment_sha256, coordinate_system:"WGS84", timezone, bounds:[W,S,E,N], prepared_at, source:DataSource{kind,url,retrieved_at,license,notice,fact_cutoff,applicability}, locations_file/supplies_file/routes_file:{path,sha256}, route_modes:[walking|driving]`. The assignment file is implied as `<locations dir>/category-assignment.json`.
- `locations.json` — `{"schema_version":3,"locations":[LocationConfig…]}` with `location_id, name, branch_label?, kind, business_kind, longitude, latitude, location_kinds[], opening_calendars[OpeningCalendar], required_qualifications[], brand|null, source, affordances{}`.
- `supplies.json` — `{"schema_version":3,"supplies":[SupplyConfig…]}`: `supply_id, location_id, product_id, seller_account_id, quotes[QuoteConfig], initial_stock, fulfillment_modes[pickup|delivery], delivery_destination_ids[], delivery_delay_seconds, required_qualifications[], source`.
- `routes.json` — `{"schema_version":3,"routes":[RouteConfig…]}`: `route_id, origin_id, destination_id, mode, status, distance_meters?, duration_seconds?, fare_fen?, fare_source_kind:"scenario", response_path?, response_sha256?, reason?, source_url, routing_instance, routing_profile foot|car, source`.
- OSRM response files (`<origin>-<destination>-response.json` by convention): `{"code":"Ok","routes":[{"distance","duration","geometry":{"type":"LineString","coordinates":[[lon,lat]…]},"legs":[{"steps":[{"mode":"walking|driving"}]}]}]}` or `{"code":"NoRoute"}`.
- `category-assignment.json` — `{kinds:{<kind>:[category_id…]}, locations:[{location_id, category_ids, object_ids, price_position_percent 5–95, source}], source}`; sha pinned in `dataset.json` and in `corpora/manifest.json`.
- `corpora/manifest.json` entries pin every map file by `path/sha256/size_bytes`.

### 3.2 Catalog files read by travel
- `catalog/rules/travel-time.toml` — `version=1`, `[factors]` `walking=1.0`, `driving_00..driving_23 ∈ [1,5]`, `[provenance.factors] {type,producer,source,artifact,method,paths=["/factors"]}`.
- `catalog/exchange-rules.json` — rules with `operator:"travel_fare"`, `minimum_fen`, `fen_per_meter` (fixture catalog has none; `tests/categories/scenario_fixtures.py` appends one); `category-contract.json` pairings `person→service action travel:driving`.
- `catalog/objects.jsonl` — object `travel-service` (category `service`), the target of travel pairings (`semantics.TRAVEL_OBJECT`).

### 3.3 Scenario fields (schema 6)
`timezone`, `random_seed` (must equal map seed), `corpus_root`, `corpus_manifest_sha256`, `map_dataset:{path,sha256,dataset_id,version}`, `locations:[{location_id}]`, `supplies:[{supply_id, initial_stock?}]`, `interaction_menus_by_location_kind` (keys == selected `kind`s), `accounts` incl. a transport role account (`transport_account_id`), agents' `home_location_id`, contacts' `receive_location_id`, tasks' `required_location_id`, work_schedule `workplace_location_id`.

### 3.4 Runtime/world state and event payloads
- `ActivityState`: `location_id` (origin for travel), `destination_id`, `travel_mode`, `route_progress_meters`, `data.route_id`, `data.travel_payment{route_id,fare_fen,currency,payer_account_id,payee_account_id,fare_source_kind,payment_timing,cancellation_refund_fen,resource_changes}`, `data.arrival{location_id,access_status,…}`, `data.category_matches`.
- `SessionState`: `kind stay|transit`, `location_id` or `origin_id/destination_id`, `name` 「去<目的地>的路上（…起）」.
- `DeliveryState`: `route_id|null`, `destination_id`, `expected_at`, `source{route…}`; `delivery_arrival` scheduled event with `order_ids`.
- Observation event (private, never prompt): `routes[]` rows (`route_id, origin_id, destination_id, mode, status, reason, distance_meters, duration_seconds(factored), free_flow_duration_seconds, travel_time_factor, fare_fen, fare_source_kind`), `reachable_places[] {location_id,name,opening_status}`, `locations[] {location_id,name,kind,business_kind,location_kinds,longitude,latitude}`, `data.supplies[]` rows incl. `delivery_destination_ids`, `delivery_delay_seconds`.
- Tool layer (prompt): location target actions `{verb travel, label 步行|驾车, travel_mode, price, duration, note "费力程度：…"}`; purchase action note "预计 HH:MM 送到"; refusal `details.next_step` strings from `wayfinding`; `unmet` values `required_location_id`, `delivery_destination`, `delivery_route`.
- `environment_event kind=location_track` (defined, never emitted): `route_id, route_response_path, route_response_sha256, sample_index, sample_count, position_lonlat[lon,lat], distance_along_route_meters, sampling_rule{method,sample_interval_seconds,departure_epoch,arrival_epoch,origin_id,destination_id,mode,sample_count}`.
- Run manifest / export `frozen_run_manifest.map_dataset` = `map_provenance` dict (see 1.2). Export `activities.jsonl` rows require `route_progress_meters, destination_id, travel_mode`; `purchases.jsonl` keeps per-order fields (no coordinates).
- Input warnings JSON: `DELIVERY_ROUTE_UNAVAILABLE{location_id,destination_id,route_status,supply_ids}`, `LOCATION_NAME_SUSPICIOUS{location_id,name,patterns}`.

## 5. What the proposal changes here

Requirement mapping (proposal §二「地图只表达可达性和时间成本」, 「同类店铺同商品，外卖全地图可达」, 评审表 rows 「地图连通且长度可计时」「全地图外卖」「位置记录与地图一致」「随机和状态可恢复」).

### 5.1 Map format — REWRITE `map_models.py` / `map_data.py`
- DELETE from `LocationConfig`: `longitude`, `latitude`, `business_kind`, `brand` (+`BrandConfig`), `opening_calendars` (+`OpeningCalendar`, `TemporalDeclaration`, `_check_weekly_overlap`, `validate_declarations`) unless the store subsystem keeps type-fixed opening hours (decision 营业与供给 — if kept, hours become a WorldMock table keyed by built-in `kind`, not a dataset declaration), `source` (per-row `DataSource`), `affordances`. KEEP `location_id`, `name`, `branch_label`, `kind` (closed `PlaceKind`, extend with the food-store types the proposal names, e.g. `cafe`, if adopted), `required_qualifications` (scenario fact, cheap to keep), and `location_kinds` **or** derive it from a WorldMock table `PLACE_KIND_ENVIRONMENTS: {kind: frozenset(LocationKind)}` (recommended: dataset supplies only id/name/kind/app bindings; see open question Q3). ADD `app_ids: tuple[str, ...]` (store→app binding, empty = pickup only) — owned by the app/store subsystem but it lives on the location record.

- ADD `MapEdge(FrozenModel)`: `origin_id: str`, `destination_id: str`, `length_meters: StrictInt = Field(gt=0)`; validator `origin_id != destination_id`. Undirected: store each unordered pair once with `origin_id < destination_id` (canonical ordering) so duplicates are detectable by equality.
- REWRITE `MapDatasetDeclaration` → `MapGraphDeclaration`: `schema_version: Literal[4]` (`MAP_SCHEMA_VERSION = 4`), `dataset_id`, `version`, `random_seed: StrictInt`, `timezone`, `generator_rule_version: Literal[1]` (binds the WorldMock generation rule), `locations_file: FileReference`, `edges_file: FileReference`. `MapGraph(MapGraphDeclaration)`: `locations: tuple[LocationConfig,…]`, `edges: tuple[MapEdge,…]` with validators: ≥2 locations; unique ids; edge endpoints exist; no duplicate unordered pair; connected (BFS over adjacency) — which implies every node has ≥1 edge; edges sorted by `(origin_id, destination_id)`; locations sorted by `location_id` (stable publication order, proposal line 178).
- REWRITE `load_map_dataset(root, reference) -> MapGraph`: same hash-pinned envelope (`{"schema_version":4,"locations":[…]}`, `{"schema_version":4,"edges":[…]}`), identity pin check, `validate_map_graph`. DELETE `_validate_route_response`, `_validate_locations` (bounds), `_validate_dates`, `_validate_sources`, `_validate_assignment_locations`, `_validate_selected_routes`, `_validate_selected_supplies`. `select_map(dataset, document) -> tuple[LocationConfig,…]` keeps pin/timezone/seed equality and the "selected ids ⊆ graph" check; it no longer filters edges — **the whole graph stays loaded** so that delivery and travel between any two selected locations use the published graph (scenario `locations` continues to pick which nodes are visible/visitable). Add a check that every selected location belongs to the graph; selecting a subset keeps connectivity because paths may traverse unselected nodes (document this; see Q4).
- ADD `src/worldmock/life/map_generate.py` (WorldMock-owned generator used by the Dataset tool and by the fixture builder): `generate_edges(location_ids: Sequence[str], seed: int) -> tuple[MapEdge,…]` — sort ids, `random.Random(seed)`: random tree by attaching each node i≥1 to a uniformly chosen earlier node (deterministic, stdlib only, no NetworkX needed at runtime), then add `EXTRA_EDGES = len(ids) // 2` non-duplicate random pairs, lengths `rng.randint(LENGTH_MIN_METERS, LENGTH_MAX_METERS)` (proposed 300–5000). Constants live in this module and are frozen in `docs/EXPERIMENT.md`. NetworkX (`random_labeled_tree`) is an alternative but the project needs byte-identical output across Windows/macOS/Linux; `random.Random` guarantees it. Loader never regenerates (proposal line 178).
- `storefront_state.map_provenance` → `{dataset_id, version, random_seed, generator_rule_version, timezone, locations_file, edges_file}`.

## 8. Open questions for the spec

1. **Connectivity vs. minimum degree** (proposal decision table "地图是否全连通"): recommend 全连通 (tree + extra edges); the loader must reject disconnected graphs even if the dataset hand-edits edges. Decide whether `validate_map_graph` also rejects graphs whose *selected* subset is disconnected when unselected nodes are excluded (Q4 below).
2. **Who runs the generator**: proposal says "注册时由 WorldMock 生成，Dataset 发布结果" and "加载和恢复直接读取固定图，不依据种子重新生成". Decide whether the loader additionally *verifies* that `edges == generate_edges(ids, seed)` (strong reproducibility, forbids hand-authored graphs) or only validates structure (allows hand-authored test graphs like `tests/life/test_wayfinding.py`). Recommendation: verify in the Dataset publication tool and in `worldmock validate`; runtime loader validates structure only.
3. **`location_kinds` ownership**: today a dataset-declared field on each location (closed set `home/office/outdoor/fitness/venue/anywhere`, runtime gate for lifestyle/content). Proposal table says locations carry only "标识、名称、WorldMock 内置地点类型". Decide: derive `location_kinds` from `kind` via a WorldMock table (consistent with "分类规则在 WorldMock 钉死"), or keep it as the one remaining per-location declaration. Affects `retrieval.place_kinds`, `validation._require_world_categories`, `tests/catalog/test_reachability_admission.py`.
4. **Graph scope vs scenario selection**: keep loading the whole graph and let paths traverse unselected nodes (simplest, keeps "任意地点间出行"), or require scenarios to select all nodes (drop `scenario.locations` selection entirely). Recommendation: drop the selection — every registered location is a world location (matches "外卖覆盖所有已注册地点"); then `LocationReference` and the "unknown map location" checks disappear.
5. **Next-step hint wording**: with full connectivity, `go_step` never says "unreachable"; decide whether multi-hop "Go via X to Y" survives (proposal line 183 only mandates relation graphs for display). Recommendation: "Go to <place>." only; delete `via` and the two UNREACHABLE constants; rewrite `contracts-活动受理拒绝码` accordingly.
6. **Ordering while on the road** (proposal line 213 "路途中下单必须明确一个地点"): today delivery address on the road = origin (`agent.location_id`), and `obtain` has no destination parameter (rulings S10/D8 removed it). Decide: keep origin as the implicit address, or add an explicit `to_place` to `obtain` items for transit only (schema and `tool_schema_sha256` change). Recommendation: keep implicit origin, state it in the spec, no request-shape change.
7. **Fixed constants to freeze** (proposal "常数表"): walking/driving m/s, driving fare (per-metre + minimum, or flat), delivery prep seconds, delivery speed, delivery fee, extra-edge count rule, edge length range (integer metres), `ROUTE_DURATION_INVALID` bound (1–86400 s still implied by length range × speed). Proposal decision row "外卖时间" recommends prep + graph time; needs numbers. Must be registered in `docs/EXPERIMENT.md` and bound into run identity (dataset-evidence §主提案复核 last paragraph: "需绑定 WorldMock 固定规则版本").
8. **Travel fare source**: proposal line 182 ("交通费用由系统按方式计算") removes `TravelFareRule`/`travel-service`; decide whether the transport ledger account (`transport_account_id`, EXPERIMENT 交通服务 10 000 000 fen) stays as the payee (recommended yes; keeps `pay_travel_fare`, ledger conservation and `test_travel_cost` with minimal change).
9. **Opening hours** (decision row "营业与供给"): if kept as per-type fixed hours, `OpeningCalendar`/`opening_hours.py` move from dataset declarations to a WorldMock table keyed by `kind`; if dropped, `opening_status`, `opening_exceptions`, `MERCHANT_CLOSED`, `location_hours_change` wake reason and the 临近闭店 commitment logic go too. This decides how much of `map_models.TemporalDeclaration` is deleted.
10. **`branch_label` / `LOCATION_NAME_SUSPICIOUS`**: keep both (display-name uniqueness is unrelated to coordinates); confirm the coordinate pattern warning stays even though the map has no coordinates.
11. **Trip identity in evidence**: confirm `trip_id = "<origin>-><destination>:<mode>"` (or `path` list) as the public-evidence object key replacing `route_id`, so `evaluation/public_evidence.py`, `review.py` forbidden keys and `DeliveryState` need one rename instead of a new evidence shape.
12. **Viewer graph display**: proposal line 183 mentions a node-relationship drawing; decide whether it is in scope for the implementation (no test or contract requires it today).
13. **Fixture strategy**: the in-repo artificial environment must grow to ≥3 nodes with edges so that travel/delivery behaviour tests stop depending on `--environment-root`; decide whether the published-environment regression (`tests/data_paths.select_environment`) remains a separate tier or whether every behaviour test must pass on the fixture (recommended: both, with the fixture as the default).
