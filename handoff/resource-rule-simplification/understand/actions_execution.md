## 8. Open questions for the spec

1. **Content-kind closed set names and claims.** The proposal fixes 文章/图文/短视频/长视频/实况. Internal identifiers (`article, image_text, short_video, long_video, live`) must be ruled, and under the frozen same-kind rule (`#spec-parallel-activities-占用声明`) `use_app` claims only its own name — so the spec must decide whether driving excludes app use entirely (recommended: add `use_app` to the driving conditional and retire `screen`, which deletes the "驾车与播客受理" row of `#time-and-energy-五类生活动作与并行准入-并行准入`) or keeps an audio-only content kind that driving tolerates; the proposal says nothing about audio-only content.
2. **Way phrase for app use.** `WAYS` needs a new (verb, action) pair; `"使用"` already maps to `consume`. Proposed `"打开" → ("interact", "use_app")` with synonyms 刷/刷一刷; the spec must fix the phrase and the object prefix (`应用：美团`) used by name resolution.
3. **App usage duration.** Proposal: "人物只选 app 和使用时长". Current frozen rule: "模型不填时长" (`#spec-agent-interaction-对象与动作选择`). Options: (a) duration = `activity_feedback_seconds` with 30-min reports (recommended; no schema change), (b) a duration way-phrase closed set. Also whether a `use_app` activity ends when the content ends with time left (proposal: draw next content and continue) versus completing early.
4. **Push wake behavior.** "推送事件复用既有调度与唤醒规则" — decide whether `app_push` is a `WakeReason` for awake persons (like `message_arrival`) or only appears in the progress layer at the next decision. Recommendation: no new wake reason; the push shows as a progress-layer `app_push` record (bounded decision count, no change to `SLEEP_ALLOWED_REASONS`). Decision table row 推送频率 (hourly, ≤1 per app per session) is assumed.
5. **Order destination en route.** Proposal: "默认给自己送至当前停留地点；路途中下单必须明确一个地点". Today `to` is the recipient and the destination is never a parameter (`#persona-prompt-交互语义-来源与去向`: "收货地点不作参数"). Either add `items[i].deliver_to` (place name) or refuse en-route orders with `ACTIVITY_PRECONDITION_UNMET`. The spec must pick one; it changes `StartActivityRequest`, `routing.ROUTE_KEYS`, bindings and the tool schema fingerprint.
6. **Work appointments and deadlines.** Proposal keeps "沿用场景的工作地点和班次" and deletes materials/acceptance; it does not say whether `appointment` (真实预约) and `due_at` survive. If deleted: `WORK_TASK_NOT_AVAILABLE`, `task_available` scheduled kind, `work_available` wake reason, `related_task_id` mail chain all go; if kept, the topic object needs `available_at`.
7. **Work hours basis.** Decision table 工作工时: recommended "实际工作秒数" (delete `effective_work_seconds`, `work_efficiency` in progress); alternative keeps efficiency. Affects `activities._advanced_activity`, `objective_progress`, `activity_progress.data.activity_efficiency`, `BodySettlement.work_efficiency` consumers.
8. **Cooking.** Decision table 做饭是否保留 (recommended delete). Determines whether `WAYS["制作"]`, `merged_selection`, `inventory_recipe`, `recipe_output_bindings`, `#tool-interaction-料理与习惯` are deleted or rewritten as a fixed-duration lifestyle activity.
9. **Food constants.** Decision table 食品常数 (200/100/600 kcal, 5/3/20 min) — values become `semantics` constants; the spec must also rule whether `basket.portion_duration` (min 60 s) and the `CONSUME_DURATION_CAP_SECONDS` 60–14400 window stay (they are single-source owners).
10. **Content re-watch and relief.** Decision table 内容进度与重看 (shared progress, allow re-watch) plus the existing relief formula `rate × effective preference ÷ exposure_count`: keep the exposure divisor, or make relief a fixed per-kind rate without taste weights? Affects `content_entertainment_relief_rate` (single-source owner) and `AgentState.taste_weights`.
11. **Random draw determinism.** Reuse `WorldState.random_state` (sha256 chain) keyed by `action_id`/`activity_id`/push hour (recommended), or advance `random_state` on every draw (changes `time_advance` chaining and every replay fixture).
12. **Session semantics for pushes.** Decision table session 的含义 (reuse stay/transit session, recommended). Pushes issued during a transit session are eligible only on that road; the spec should state that `route_ended` on arrival does not consume them (progress kept) and that a push's session check is made at open time (no cleanup hook).
13. **Rejection code additions.** `APP_CONTENT_EMPTY` (new) versus reusing `ACTIVITY_PRECONDITION_UNMET`; whether ordering via an unbound app is `SUPPLY_NOT_AT_STORE` (existing) or a new `APP_NOT_BOUND`.
14. **Schema version and identities.** One bump of `WORLD_SCHEMA_VERSION` (9→10), `RuntimeScenario.schema_version` (6→7), `catalog_version` major, and the tool/prompt fingerprints — the spec's "旧格式直接拒绝" clause should list all four so the error-contract tests and `test_engine_package_resources` byte checks are updated together.
