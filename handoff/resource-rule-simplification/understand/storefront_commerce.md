3. Exchange engine: removal of purchase pairing / `evaluate_purchase` coefficient, `FoodEnergyRule`, `InventoryTransformRule`; `purchase_amount` becomes price × quantity + fee.
4. Entertainment/app subsystem: the shared `AppCatalog` (`apps.py`) — same `app_id` identity for restaurants (store.app_ids) and contents; push notifications are not this subsystem's concern but read the same catalog.
5. Persona coverage / run_setup / Dataset `simulate_phone.py` + `labelkit_input.py`: app names now from the catalog; `purchase_apps_by_seller` and `content_apps_by_id` deleted; `purchases.jsonl` `app_id` column replaces seller-based inference (dataset repo change, out of WorldMock scope but must be scheduled).
6. Candidates/presentation: supply-keyed visibility credentials, rotation window keyed by `supply_id` (`observe`, `candidates`, `rotation`, `presentation_state`) must be re-keyed to `(store_id, food_id)` or dropped (Q6).

Scenario/world schema bumps: scenario 6 → 7 (drop `products/supplies/price_changes/product_releases/recipe_output_bindings/phone_simulation_config*`), world 9 → 10 (`DeliveryState` fields, dropped `supply_stock/supply_quotes/opening_exceptions/visible_supply_*`), export manifest `purchases.jsonl` columns, checkpoint/restore validation (`validate_storefront_state` → environment identity + rules version).

9. Host (`custom/agents/life_agent.py`, `routing.py`) and Dataset tooling consume the same `items[]` contract; only the `from` semantics (app name instead of phone-config channel) change.

## 8. Open questions (decisions the spec must make)

1. **Opening hours** — proposal decision table "营业与供给: 不设库存、店铺全天服务（推荐）vs 无库存、按类型固定营业时间". Decides whether `opening_hours.py`, `MERCHANT_CLOSED`, rhythm's "store open" meal logic and `tests/life/test_opening_hours.py` are deleted or replaced by a per-kind constant table.
2. **Delivery time** — "外卖时间: 固定备餐＋图上配送时间（推荐）vs 全部固定送达时间"; freeze `DELIVERY_PREP_SECONDS`, `DELIVERY_SPEED_MPS` (and whether the hunger-window assumption "一小时覆盖外卖 20–40 分钟" in EXPERIMENT.md still holds).
3. **Seller accounts** — the proposal does not say who receives payment. Options: one merchant account per store created at registration (`merchant:<location_id>`), or one per kind; `ORDER_SELLER_MISMATCH` disappears either way. Also whether `required_qualifications`/`LOCATION_ACCESS_DENIED` survive (not mentioned by the proposal; "其他地点沿用各自系统固定服务" suggests deletion for stores).
4. **Delivery fee routing** — "费用为商品价加系统固定配送费": fee to the merchant, to a per-app platform account, or destroyed; value of `DELIVERY_FEE_FEN`.
5. **App selection when `from` is null** — a store bound to several apps: system picks deterministically (and records it) or requires the person to name the app; and whether `from=<app>` with a pickup way is a mismatch or ignored.
6. **Visibility credentials / rotation** — with fixed per-kind menus and name-based buying, keep `visible_supply_ids` re-keyed to `(store, food)` for presentation only, or delete the credential and `SUPPLY_NOT_VISIBLE`; interacts with the candidates subsystem (decision table does not list it).
7. **"到店消费按字面落实为在店购买和进食，不开放取餐带离"** — today pickup leaves goods in the store's holdings (no backpack), which already prevents take-away; confirm no new "buy-and-eat" merged action is required and that holdings left in a store remain purchasable/eatable later.
8. **Ordering en route** — proposal: "路途中下单必须明确一个地点" vs frozen "收货地点不作参数" (`persona-prompt-交互语义-来源与去向`). Either add an explicit destination argument for en-route delivery or keep today's rule (destination = departure location / reject with "Place the order before departing").
9. **Same-kind food binding form** — decision "同类店铺的食品绑定: 精确绑定并校验同类一致（推荐）vs 按店铺类型填写绑定"; decides the food `stores` field shape and the registration error for partial bindings.
10. **Cooking** — "做饭是否保留: 删除做饭和食材配方（推荐）vs 保留为固定耗时生活活动"; decides deletion of `inventory_recipe.py`, way 「制作」, `recipe_output_bindings` and the dayrun "home stock of 7 breakfasts" assumption (`spec-life-realism-世界素材品类要求`).
11. **Food constants** — "食品常数: 采用表内热量和食用时长（推荐）vs 重新标定"; `basket.portion_duration`'s `max(60, round(整份时长 × 份量))` keeps working with the category duration.
12. **Error-code naming** — keep `SUPPLY_*` code names (host, `NAME_REJECTION_CODES`, quality report `name_rejections`, Dataset tooling depend on them) or rename to `FOOD_*`; add `APP_NOT_BOUND` or fold into `FULFILLMENT_NOT_SUPPORTED` with an `unmet` value.
13. **World/scenario/export identity** — which fields replace `map_provenance` in the run manifest (environment id + content hash + `RULES_VERSION`), and whether `purchases.jsonl` keeps `fact_kind` rows `order_attempt`/`app_browse` unchanged.
